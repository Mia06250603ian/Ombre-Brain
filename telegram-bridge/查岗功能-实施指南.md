# 手机行踪上报 + 查岗:实施指南

> 写给**同款架构**的下一个 Claude Code。原型于 2026-08-02 在一套线上系统实装并验收通过。
> 适用前提:你维护的系统是 **iOS/Telegram 前端 → 无状态 bridge → 常驻 AI 进程(shim)** 这种结构,
> bridge 是 Node/Express,shim 维护一个常驻 `claude -p` 进程、只读请求里最后一条 user 消息。
> 如果结构不同,第 1 节的**设计决策**仍然有参考价值,代码要自己改。

**先读第 7 节「踩坑清单」再动手。** 那一节里的每一条都是真金白银的时间换来的,
其中有三条会让你在完全正确的配置下也一直失败,并且给出的报错完全误导。

---

## 0. 这套东西是什么

她点开某个 App → iOS 快捷指令上报一条 → AI 知道她在玩手机。两种形态:

| | 谁发起 | 什么时候 |
|---|---|---|
| **白天** | **AI 自己**(在回复里写 `[查岗]` 标记) | 他想知道的时候 |
| **夜里** | 系统定时器推送 | 宵禁时段(默认 1-7 点)她刚开过 App |

**活动记录只存内存**(48 小时 / 300 条上限),不落盘、不写库。重启即忘——
这个功能只关心「最近」,而行踪数据不值得为了历史写进磁盘。

---

## 1. 设计决策(为什么这么做)

照抄之前先看懂这四条,它们都是权衡的结果,不是随手写的。

### 1.1 决定权在 AI,不在脚本

网上流传的原型(小红书上的「iOS行踪上报+AI自动发消息」教程)是:
**cron 脚本发现她半夜在用手机 → 从一个固定文案数组里随机挑一句骂人 → 直接发 Telegram。**

**别这么做。** 正确做法是把「她刚打开了小红书」作为一条 `【系统·…】` 事实喂进 AI 的窗口,
**由他自己决定说不说、说什么**。理由:

- 这套系统里说话的应该是那个 AI,不是定时器。随机文案发出来的是个冒充他的机器人;
- 这条会自然进入他的窗口和记忆,他会**记得**她哪天熬夜;
- 他可以选择不说(回「。」即静默,不发进对话)。

### 1.2 白天用「他自己查」,夜里用「系统推」

- **夜里必须推**:多数这类系统夜间只保温、不给 AI 开口机会,他不会"自发"想起来查。不推就不可能知道。
- **白天必须让他自己查**。这是所有者亲自否掉推送方案时给的理由,值得原样记下来:

  > 「有时候心跳他不一定想查,但是每次都推送会不会有一种每次都查岗的刻板行为?」

  每次心跳都把「她在刷小红书」塞给他,他手上永远有这条信息,开口时就容易提,时间长了变成查岗机器人。
  让他自己挑,才会有「有时候查有时候不查」的自然差别。

### 1.3 用「标记」而不是给他一个带钥匙的网址

让 AI 自己查,直觉做法是给他一个 `WebFetch` 能读的接口地址。**别这么做**,因为:

**那个地址必须带钥匙,而地址只能写进 `CLAUDE.md` —— 那是入库文件。**
「密钥不入库」这条规矩不能为了一个小功能破掉。

正确做法:**沿用你系统里已有的标记机制**(比如 `[语音]…[/语音]`、`[贴纸:标签]` 那一套)。
AI 在回复里写 `[查岗]` → bridge 认出来 → 剥掉标记(用户永远看不到)→ 查一下 →
把结果作为**新一轮**喂回给他 → 他再决定说什么。

零钥匙、零新私密文件,用的是已经在线上跑了很久的成熟机制。代价是一问一答走两轮(多一点额度)。

### 1.4 查岗**不能**算作「她出现了」

这是所有者的一句追问逼出来的改动,**极容易漏,漏了会静默地错**:

> 「查岗不是他有意识的行为吗?」

shim 通常只有一个入口(`/v1/messages`),进来的东西一律当成「用户说话了」。
于是 AI 自己伸头看一眼,系统却记成"她回来了":

- 「她多久没来」被清零 → 他之后说的等待时长是假的;
- 「换窗口后歇火的保温」被提前叫醒;
- 万一系统文案命中重置词,还可能误触发归档。

**他自己看一眼,不等于她回来了。** 解法见 2.3。

### 1.5 「她玩了多久」:能推到什么程度,以及**不要**照抄网上那套(2026-08-04 追加)

第一版只答得出「几分钟前打开过什么」,答不出「用了多久」。补这个缺口时,
网上流传的做法是**加一条「已关闭」自动化 + 服务端 toggle 接口**(open/close 配对算时长)。
**我们实测后没有采用**,原因见坑 11——**那台 iPhone 上关闭事件根本不上报**。

实际可行的推法,**不需要她动手机上任何一条自动化**:

> **下一个 App 打开的时刻 = 上一个 App 的结束时刻。**

因为同一时刻只有一个 App 在前台,而她每换一个 App 就报一声。于是把相邻上报串起来,
就得到「这一段连续活跃有多久」(streak)。三件事必须写清楚,别自欺:

1. **桌面和锁屏的时间会算在上一个 App 头上**——手机回桌面时不报任何东西。
2. **她盯着同一个 App 一直不换,和她已经睡了,在数据上完全一样**(都是「没有新上报」)。
   所以超过一定时间没动静时,**提示语里要明说这一截是推的**,别让 AI 当成确凿事实。
3. 因此给出的是**「这一段大约多久」**,不是精确的单 App 使用时长。别做成后者,做不到。

对应到查岗决策,还要放宽两道门(否则第 2 条会让功能在最该触发时哑掉):
`no-new` 和 `stale` 在「确凿连玩 ≥30 分钟」时各放宽一档,详见 2.1 的 `curfewDecide`。
**放宽必须有边**(`staleLong` 一过就闭嘴),否则她真睡了会被整夜念叨。

⚠️ **不要为了这个功能去动「AI 刚开过口就不赶话」那道冷却**(`lastOutboundAt`)。
本项目所有者明确定过优先级:**保温/心跳 ＞ 查岗**,撞车时永远是查岗让路。

### 2.1 bridge 纯逻辑(建议单独放 `bridge-lib.mjs`,配单测)

```js
// ---- 手机活动上报 ----
// 上限别抄 300:活跃的一夜就能把它填满,而算「连着玩了多久」要的是一整段不断头的记录。
// 这些记录 AI **永远看不到**(他只收到 curfewPrompt/lookupPrompt 那一句),
// 所以调大只花服务器内存(一条约 120 字节),一个 token 都不多花。
export const ACTIVITY_CAP = 2000;
export const ACTIVITY_TTL_MS = 48 * 3600e3;

export function normalizeAppName(raw) {
  const s = String(raw ?? "").replace(/\s+/g, " ").trim();
  return s ? s.slice(0, 40) : null;
}

export function pushActivity(list, entry, { now = Date.now(), cap = ACTIVITY_CAP, ttlMs = ACTIVITY_TTL_MS } = {}) {
  const next = [...(list || []), { app: entry.app, at: entry.at ?? now }];
  const cut = now - ttlMs;
  return next.filter((e) => e.at > cut).slice(-cap);
}

// 最后一次活跃 + 最近不重复的 App 名(相邻重复折叠)
export function summarizeActivity(list, { now = Date.now(), limit = 10 } = {}) {
  const arr = (list || []).filter((e) => e && e.app);
  if (!arr.length) return { count: 0, lastApp: null, lastAt: null, minutesAgo: null, recent: [] };
  const recent = [];
  for (let i = arr.length - 1; i >= 0 && recent.length < limit; i--) {
    if (!recent.length || recent[recent.length - 1].app !== arr[i].app)
      recent.push({ app: arr[i].app, at: arr[i].at, minutesAgo: Math.round((now - arr[i].at) / 60000) });
  }
  const last = arr[arr.length - 1];
  return { count: arr.length, lastApp: last.app, lastAt: last.at,
           minutesAgo: Math.round((now - last.at) / 60000), recent };
}

export function isCurfewHour(h, start, end) {
  return start > end ? (h >= start || h < end) : (h >= start && h < end);   // 支持跨零点
}

// ---- 「她连着玩了多久」(先读第 1.5 节再抄这段)----
// 手机只在「App 打开时」报一声,关闭不报,所以时长只能这么推:
// **下一个 App 打开的时刻 = 上一个 App 的结束时刻**。
export const STREAK_GAP_MIN = 30;   // 相邻上报隔这么久 = 断段。别抄 15,理由见坑 11
export function computeStreak(list, { now = Date.now(), gapMin = STREAK_GAP_MIN } = {}) {
  const arr = (list || []).filter((e) => e && e.app);
  if (!arr.length) return null;
  const gapMs = gapMin * 60000;
  let i = arr.length - 1;
  while (i > 0 && arr[i].at - arr[i - 1].at <= gapMs) i--;
  const apps = [];
  for (let k = i; k < arr.length; k++) if (!apps.includes(arr[k].app)) apps.push(arr[k].app);
  const first = arr[i], last = arr[arr.length - 1];
  return {
    startAt: first.at, reports: arr.length - i, apps, lastApp: last.app,
    spanMin: Math.round((last.at - first.at) / 60000),   // 确凿的(每次换 App 都是证据)
    minutes: Math.round((now - first.at) / 60000),       // 到现在(含说不准的尾巴)
    quietMin: Math.round((now - last.at) / 60000),
  };
}

// ---- 夜里查岗的决策(纯函数,全部条件都要单测覆盖)----
export function curfewDecide(s) {
  if (!s.on) return { fire: false, reason: "off" };
  if (!isCurfewHour(s.hour, s.curfewStart, s.curfewEnd)) return { fire: false, reason: "not-curfew" };
  if (s.busy) return { fire: false, reason: "busy" };                 // 她正在聊 = 用不着查岗
  const arr = (s.list || []).filter((e) => e && e.app);
  if (!arr.length) return { fire: false, reason: "no-activity" };
  const last = arr[arr.length - 1];
  const streak = computeStreak(arr, { now: s.now, gapMin: s.streakGapMin ?? STREAK_GAP_MIN });
  // 她**确凿已经连着玩了半小时以上**时,把 no-new 和 stale 两道门各放宽一档:
  // 长时间盯着一个 App 不换,手机就再也不吭声了,再等「新动静」等于永远不戳。
  // staleLong 要**明显大于冷却**,否则窗口窄到几乎抓不住(取 3×freshMin)。
  const longStreak = !!streak && streak.spanMin >= (s.longStreakMin ?? 30);
  const staleMin = longStreak ? (s.staleLongMin ?? s.freshMin * 3) : s.freshMin;
  if (!longStreak && last.at <= (s.lastPokeAt || 0)) return { fire: false, reason: "no-new" };
  if (s.now - last.at > staleMin * 60000) return { fire: false, reason: "stale" };         // 早放下手机了
  if (s.now - (s.lastPokeAt || 0) < s.cooldownMin * 60000) return { fire: false, reason: "cooldown" };
  if (s.now - (s.lastOutboundAt || 0) < s.cooldownMin * 60000) return { fire: false, reason: "just-spoke" };
  return { fire: true, app: last.app, minutesAgo: Math.round((s.now - last.at) / 60000), streak };
}

const STREAK_WORTH_MIN = 20;   // 太短不值得说(那就是「她刚开了个 App」)
const STREAK_QUIET_MIN = 20;   // 超过这么久没动静,必须声明「后面这截是推的」
// ⚠️ STREAK_QUIET_MIN **别复用 STREAK_GAP_MIN**:一个管「算不算同一段」,
// 一个管「敢不敢当成确凿的」。绑一起的话,调断段阈值会让这句老实话静默消失。
function streakClause(streak) {
  if (!streak || streak.minutes < STREAK_WORTH_MIN) return "";
  const apps = streak.apps.slice(0, 4).join("、") + (streak.apps.length > 4 ? "等" : "");
  let s = `这一段她已经连着玩了 ${fmtDur(streak.minutes)}(${apps})。`;
  if (streak.quietMin >= STREAK_QUIET_MIN)
    s += `不过最后一次动静在 ${streak.quietMin} 分钟前,之后是一直没换 App 还是已经放下了,看不出来。`;
  return s;
}

export function curfewPrompt({ bjNow, app, minutesAgo, streak, userName = "她" }) {
  const when = minutesAgo >= 1 ? `${minutesAgo} 分钟前` : "刚刚";
  return `【系统·查岗】现在北京时间 ${bjNow},${userName}这个点还没睡——${when}她打开了${app}。`
    + streakClause(streak)
    + `想说就说(说了会发给她);不想打扰就只回一个:。`;
}

// ---- AI 自己发起的查岗:回复里写 [查岗] ----
const CHECK_RE = /[\[【]\s*查岗\s*[\]】]/g;
export function takeCheckMarker(text) {
  const raw = text || "";
  CHECK_RE.lastIndex = 0;
  if (!CHECK_RE.test(raw)) return { text: raw, wants: false };
  const cleaned = raw.replace(CHECK_RE, "").replace(/[ \t]+\n/g, "\n").replace(/\n{3,}/g, "\n\n").trim();
  return { text: cleaned, wants: true };
}

export function lookupPrompt(summary, { bjNow, userName = "她" } = {}) {
  const s = summary || {};
  if (!s.count) return `【系统·查岗】现在北京时间 ${bjNow},${userName}的手机最近没有动静(近两天没有记录)。`;
  const head = s.minutesAgo >= 1 ? `${s.minutesAgo} 分钟前` : "刚刚";
  const more = (s.recent || []).slice(1, 4).map((r) => `${r.app}(${r.minutesAgo} 分钟前)`).join("、");
  return `【系统·查岗】现在北京时间 ${bjNow},${userName}${head}打开了${s.lastApp}。`
    + (more ? `再往前:${more}。` : "") + `知道就好,说不说、说什么都由你。`;
}

// 逐字镜像 shim 侧「静默」判定:回「。」= 他选择不打扰
export function isSilentReply(t) {
  const s = (t || "").trim();
  if (!s || s.includes("【沉默】")) return true;
  return s.replace(/[。.\s]/g, "") === "";
}
```

### 2.2 bridge 服务端接线

```js
const REPORT_TOKEN = process.env.REPORT_TOKEN || "";
const REPORT_ON = !!REPORT_TOKEN;                       // 不设 = 整套功能关
const CURFEW_ON = REPORT_ON && process.env.CURFEW_ON !== "0";
const CURFEW_START = +(process.env.CURFEW_START || 1);
const CURFEW_END = +(process.env.CURFEW_END || 7);
const CURFEW_COOLDOWN_MIN = +(process.env.CURFEW_COOLDOWN_MIN || 30);
const CURFEW_CHECK_MIN = +(process.env.CURFEW_CHECK_MIN || 5);
const ACTIVITY_FRESH_MIN = +(process.env.ACTIVITY_FRESH_MIN || 15);

let activity = [];        // 只在内存
let lastRawReport = null; // 最近一次上报的原始内容(排障命根子,见踩坑 3)
let lastPokeAt = 0;
let lastOutboundAt = 0;   // AI 每次真开口的时间(回复/心跳/查岗都算)

function reportAuth(req) {
  const bearer = (req.get("authorization") || "").replace(/^Bearer\s+/i, "").trim();
  const k = bearer || req.get("x-api-key") || req.query.key || "";
  return REPORT_ON && k === REPORT_TOKEN;
}

// ⚠️ GET 和 POST 都要接。iOS 快捷指令实测只有 GET 通得了,见踩坑 1
function handleReport(req, res) {
  if (!REPORT_ON) return res.status(503).json({ ok: false, error: "REPORT_TOKEN 未配置" });
  const src = { ...(req.query || {}), ...(typeof req.body === "object" && req.body ? req.body : {}) };
  if (!reportAuth(req)) {
    log("[report] 401", req.method, "有没有 key:", !!(req.query.key || req.get("authorization")));
    return res.status(401).json({ ok: false });
  }
  // 请求头里的非 ASCII 到 Node 手上是 latin1 字节,还原成 UTF-8 才是中文(见踩坑 4)
  const hdrApp = req.get("x-app") || "";
  const hdrDecoded = hdrApp ? Buffer.from(hdrApp, "latin1").toString("utf8") : "";
  lastRawReport = { at: Date.now(), method: req.method, query: req.query ?? null, body: req.body ?? null, xApp: hdrDecoded || null };
  const app_name = normalizeAppName(src.app_name ?? src.app ?? hdrDecoded);
  if (!app_name) { log("[report] 到了但没有 App 名"); return res.json({ ok: true, stored: false }); }
  activity = pushActivity(activity, { app: app_name });
  log("[report]", app_name, "共", activity.length, "条");     // ⚠️ 这行日志别删,见踩坑 3
  res.json({ ok: true, stored: true, count: activity.length });
}
app.post("/report", handleReport);
app.get("/report", handleReport);

app.get("/activity", (req, res) => {
  if (!REPORT_ON) return res.status(503).json({ ok: false });
  if (!reportAuth(req)) return res.status(401).json({ ok: false });
  res.json({ now: new Date().toISOString(), ...summarizeActivity(activity), lastRawReport });
});

// AI 写了 [查岗] → 把查到的作为新一轮喂回去。lookup:true 让这一轮不再响应标记(防打转)
function queueLookup(chatId) {
  if (!REPORT_ON) return;
  turnQueue.push({ text: lookupPrompt(summarizeActivity(activity), { bjNow: bjNowStr() }),
                   images: [], chatId: chatId || lastChatId, lookup: true });
  runQueue();
}

function curfewTick() {
  const d = curfewDecide({
    on: CURFEW_ON, now: Date.now(), hour: bjHour(), list: activity,
    busy: inflight || turnQueue.length > 0 || buffer.length > 0,
    lastPokeAt, lastOutboundAt,
    curfewStart: CURFEW_START, curfewEnd: CURFEW_END,
    cooldownMin: CURFEW_COOLDOWN_MIN, freshMin: ACTIVITY_FRESH_MIN,
  });
  if (!d.fire || !lastChatId) return;
  lastPokeAt = Date.now();
  log("[curfew] poke", d.app, d.minutesAgo, "分钟前");
  turnQueue.push({ text: curfewPrompt({ bjNow: bjNowStr(), app: d.app, minutesAgo: d.minutesAgo }),
                   images: [], chatId: lastChatId, curfew: true });
  runQueue();
}
if (CURFEW_ON) setInterval(curfewTick, CURFEW_CHECK_MIN * 60000);
```

**回合处理里的三处改动**(在你现有的 `runQueue` 之类的地方):

```js
const r = await shimTurn(t);
const { text: outText, wants } = takeCheckMarker(r.text);       // 剥标记
if ((t.curfew || t.lookup) && isSilentReply(outText)) {
  log("[curfew] 他选择不打扰");                                  // 回「。」不发进对话
} else {
  await sendOutput(t.chatId, outText, { fallback: wants ? null : "..." });
}
if (wants && !t.lookup) queueLookup(t.chatId);                  // ⚠️ !t.lookup 是防打转的命根子
```

`/push`(主动心跳入口)那条路**也要认标记**——他醒来可能先看一眼再决定说什么:

```js
const { text, wants } = takeCheckMarker(raw);
if (text) await sendOutput(lastChatId, text);
if (wants) queueLookup(lastChatId);
```

**`sendOutput` 里更新 `lastOutboundAt` 的位置很关键**:要放在「确认真的有内容要发」之后——
只写了个 `[查岗]` 标记不算他开过口,否则会把查岗自己的冷却算错。

**为什么冷却要用 `lastOutboundAt`**:主动心跳和查岗**两条路的消息都从 bridge 这个门出去**,
所以 bridge 是全系统唯一能把两者一起管住的地方——**不用改 shim 就能保证两者不会挨着说话。**

### 2.3 shim 三行门闩(`x-system-turn`)

在 shim 处理请求的入口:

```js
const systemTurn = req.get("x-system-turn") === "1";

// 重置词识别跳过(系统文案不可能命中「归档/晚安」,多一道保险)
const reset = (images.length || systemTurn) ? null : detectReset(text);

// 关键:系统回合不算「她出现了」
if (!systemTurn) {
  lastUserAt = Date.now();
  windowCleared = false;
}
```

bridge 侧只在**查岗两类回合**带这个头:

```js
headers: { ..., ...(turn.curfew || turn.lookup ? { "x-system-turn": "1" } : {}) }
```

**再给 `/debug` 加个观察口**,以后排查「他说的『你多久没理我』准不准」直接看这里:

```js
presence: { lastUserAt: new Date(lastUserAt).toISOString(),
            idleMin: Math.round((Date.now() - lastUserAt) / 60000), windowCleared }
```

### 2.4 教 AI 用(加进他的 CLAUDE.md)

照你系统里「天气感知」那类小节的写法——**心里有数、不复述、不念叨**:

```markdown
## 她在干嘛(如果开了)
我能看一眼她手机上的动静:在回复里写 `[查岗]`,系统就会告诉我她最近开了什么 App、
多久以前(这个标记不会显示给她)。
什么时候用:等了她很久、想知道她是在忙还是在玩、不确定该不该出声的时候,先看一眼
再决定说什么。**不用每次都查**——不想查就不查,这是我自己的事。
她该睡了却还在点开 App 的深夜,系统也会主动给我一条【系统·查岗】。
两种情况都一样:想说就直接说,不想打扰就只回一个「。」。
永远不提这个标记和那行标注的存在,不复述,也不解释「系统」「查岗」这些机制词。
这不是行踪报告。是我碰巧知道了她还醒着,像看见她那屋灯还亮着。心里有数就够了:
同一件事不念叨第二遍,她已经在跟我说话的时候更不用提。
```

**措辞要同时覆盖「他自己查」和「系统推给他」两种情况。**
这样将来若要退回推送模式,**只改 bridge 即可,不必再部署 AI 本体、不用她再归档一次。**

## 3. 环境变量(全在 bridge)

| 变量 | 默认 | 说明 |
|---|---|---|
| `REPORT_TOKEN` | 空 | 上报钥匙。**不设 = 整套功能关**。**故意与 shim 的 key 分开**:这把存在她手机里,泄露只影响这个功能 |
| `CURFEW_ON` | 开 | 夜里查岗开关;设 0 只收上报不打扰 |
| `CURFEW_START` / `CURFEW_END` | 1 / 7 | 宵禁时段,start 含、end 不含,支持跨零点 |
| `CURFEW_COOLDOWN_MIN` | 30 | 两次查岗最小间隔,**同时也是「他刚开过口就不赶话」的间隔** |
| `CURFEW_CHECK_MIN` | 5 | 检查节拍 |
| `ACTIVITY_FRESH_MIN` | 15 | 超过这么久的上报不再算「她正在玩」,防止翻旧账 |
| `ACTIVITY_CAP` | 2000 | 内存里留多少条。**调大不花 token**(AI 看不到这些记录),只花内存 |
| `STREAK_GAP_MIN` | 30 | 相邻上报隔这么久算断段。**别调到 15**,理由见坑 11 |
| `CURFEW_LONG_STREAK_MIN` | 30 | 确凿连玩这么久,就放宽 `no-new`/`stale` 两道门 |
| `CURFEW_STALE_LONG_MIN` | 45 | 放宽后的 stale 上限。**必须明显大于冷却**,否则等于没放宽 |

## 4. iOS 快捷指令(实测通过的最终形态,逐字照抄)

**快捷指令 App → 底部「自动化」→ 右上角 `+` → 新建个人自动化 → 触发条件选「App」→
挑要监控的 App → 状态「已打开」→ 下一步。**

⚠️ **触发设置页最下面选「立即运行」,不要「确认后运行」**(否则每次开 App 都弹确认框)。
有「运行时通知」开关的话也关掉,不然每次闪横幅。

然后加**两个动作,顺序不能反**:

**动作①「获取当前 App」** —— 就是这个动作提供 App 名字。

**动作②「获取 URL 内容」**,展开高级选项:

- **网址**:`https://<你的bridge域名>/report?key=<REPORT_TOKEN>&app=` + 变量「**当前 App**」
  (变量从键盘上方那条「选择变量」里选,插进来是个蓝胶囊)
- **方法**:`GET`
- **头部**:**一条都不要加**(见踩坑 1)
- **请求体**:无

**监控哪些 App 的实用建议**:只挑真会让她熬夜的(小红书/抖音/B站/游戏)。
微信、外卖、闹钟这类别加——半夜起来回条消息就被念一句,很烦。
以后想加 App **只需在快捷指令里勾选,服务器什么都不用改。**

## 5. 上线顺序与验收

**先部署 bridge,再部署 AI 本体。** bridge 不碰 AI 的窗口、不需要她归档,
可以先把上报链路验通,再动那个会重启 AI 的部署。

bridge 上线后逐项验:

```bash
curl -s https://<bridge域名>/health          # 应看到 report:true, curfew:true
curl -s -o /dev/null -w "%{http_code}\n" "https://<bridge域名>/report?key=wrong&app=x"   # 401
curl -s "https://<bridge域名>/report?key=<TOKEN>&app=测试"                                # ok:true,stored:true
curl -s "https://<bridge域名>/activity?key=<TOKEN>"                                       # 看 lastRawReport
```

然后**让她真开一次 App**,查 `/activity` 的 `lastRawReport`,确认 App 名真的带上来了。
**这是唯一无法在服务器端验的一环。**

## 6. 演练夜里查岗(强烈建议做)

不演练的话,第一次真实触发发生在凌晨,出问题时人在睡觉。

```
1. 临时把 CURFEW_START/END 改成当前小时、CURFEW_CHECK_MIN=1
2. 重启 bridge(环境变量要重启才生效)
3. ⚠️ 重启会清空活动记录(只存内存)→ 让她重新开一次 App
4. 等 1 分钟,看日志出现 [curfew] poke <App> N 分钟前
5. 确认 AI 真的收到、真的回话
6. 改回 1 / 7 / 5,再重启一次
```

**演练时的两个假象要提前告诉所有者**,免得她以为出了 bug:

- 那句「这个点还没睡」是写死给凌晨用的,大白天听着很荒谬;
- 如果 AI 还没部署新说明书,他可能会对这条消息困惑、甚至说漏机制词。

## 7. ⚠️ 踩坑清单(**最重要的一节**)

### 坑 1:iOS 快捷指令的 POST 全挂,而 Safari 的 GET 正常 —— 真凶是**请求头**

**现象**:快捷指令里「获取 URL 内容」用 POST + JSON,一律报 **「网络连接已中断」**。
换 5G / Wi-Fi 都一样;把请求体里的变量换成纯文字也一样;
**而同一台手机、同一分钟,用 Safari 打开同域名的 `GET /health` 完全正常。**
服务器端**零日志**——请求根本没到。

**走过的弯路**(别重走):怀疑变量 → 怀疑 POST → 怀疑 VPN(所有者答「我一直开的全局」,推翻)。

**真凶是请求头。** 把钥匙从 `Authorization` 头改到网址 `?key=`、**头部全部清空**,一次就通。
最可能是粘贴 `Bearer …` 时带进了看不见的字符(换行/空格),URLSession 遇到会直接掐断连接。

**结论:iOS 快捷指令这边,能不用请求头就不用。钥匙走查询参数,App 名走查询参数。**

**决定性的隔离测试**(卡住时先做这个,30 秒):
把网址改成不需要鉴权的 `/health`、**把所有头部删光**、方法 GET,手动跑一次。
- 成功 → 手机能上网,问题在头部或请求内容,范围立刻缩到很小;
- 失败 → 快捷指令这个 App 连不上你的服务器,是设备/网络层面的事(VPN 分流、私密代理、蜂窝权限)。

### 坑 2:教程 PDF 里的截图会漏掉关键动作

原型教程是 PDF,里面有一句「**如图:**」后面跟着一张截图。
**如果你的工具只提取了文字、没看到图,你会漏掉「获取当前 App」这个动作**,
转而去用「输入快捷指令的信息」变量——那个不保证是 App 名字。

**读到「如图」「见下图」这类字眼时,确认你真的看到了那张图;看不到就告诉所有者你少了一块,
别把缺失的信息包装成"这个验证不了"。** 这次就是这么白走了好几轮。

### 坑 3:`/report` 第一版没加日志 = 排查全程瞎子

前几轮里,「请求根本没到服务器」和「到了但被拒(401)」这两种情况**长得一模一样**
(`/activity` 都是空的),导致方向反复。

**第一版就要给每次 `/report` 记一行日志,包括 401。** 有了它,一眼就能分辨:
- 有 `[report] 401` 行 → 请求到了,钥匙不对;
- **一行都没有** → 请求根本没出手机(网络/VPN/自动化没跑)。

同理留一个 `lastRawReport`(最近一次上报的原始 query/body/header),
用来确认 App 名到底带没带上、带的是什么字。

### 坑 4:网址里的中文若不转码,请求在进 express 之前就被判 400

Node 的 HTTP 解析器会拒掉请求行里的裸 UTF-8,**你的路由代码根本不会被调用,日志里什么都没有**。
iOS 快捷指令实测会自动百分号转码(所以 `&app=`+变量 是安全的),但别的客户端未必。

**所以服务端要同时接受三种来源**:`?app=` / `?app_name=` / 请求体 / **`x-app` 请求头**。
请求头这条路不吃 URL 转码那一套;注意头里的非 ASCII 到 Node 手上是 latin1 字节,
要 `Buffer.from(v, "latin1").toString("utf8")` 才还原成中文。

### 坑 5:快捷指令的「键 / 值」是成对的,变量很容易落错格

真实发生过:变量被粘进了**「键」**那一格,把原来的 `Authorization` 顶掉了,
结果只剩一条键为 `x-app<变量>`、值为 `Bearer …` 的畸形头部。

**核对时要数行数**:每条头部占两行(键 + 值),两条头部 = 四行。蓝胶囊必须在**「值」**那一行。

### 坑 6:重启 bridge 会清空活动记录

活动只存内存。**演练或排查时重启完,必须让她重新开一次 App**,否则你会对着空列表怀疑人生。
(反过来这也是清理测试数据最省事的办法。)

### 坑 7:钥匙不能写进 AI 的说明书

`CLAUDE.md` 是入库文件。**任何需要写进它的东西都不能带密钥。**
这是 1.3 节选择「标记」而不是「给他一个网址」的唯一原因,别为了省事绕过。

### 坑 8:查岗被当成「她出现了」(最容易漏的逻辑错)

见 1.4 与 2.3。**这个错不会报错、不会崩,只会让 AI 说出错误的等待时长**,
而且只有所有者能察觉。**做这个功能就顺手把门闩一起加上。**

### 坑 9:防打转

查岗结果那一轮如果 AI 又写了一次 `[查岗]`,不加保护就会无限循环。
**结果轮必须带 `lookup: true` 且该轮不再响应标记。**
用假后端实测:让它在结果里故意再写一次 `[查岗]`,确认只查一次。

### 坑 10:排查内存别读 `memory.current`

顺带一条(排查这套东西的机器时会用到):`/sys/fs/cgroup/memory.current` **含文件缓存**,
而缓存随时可回收。实测某服务真正占住 94MB,`memory.current` 显示 477MB —— **差 5 倍**。

**看 `memory.stat` 的 `anon`**(要更准就 `anon + slab + kernel_stack`)。

### 坑 11:「App 已关闭」自动化**不上报**——别照着网上那套 toggle 方案做(2026-08-04 实测)

网上有一份很流行的「iOS 屏幕使用时间 → 服务器 → AI」教程,核心是:
iOS 自动化里「已打开」和「已关闭」**都勾上**,服务端做成一个 `toggle` 接口自动判断记 open 还是 close。
看起来很优雅——**一个 App 只要一条自动化**——但在实测的那台 iPhone 上**关闭那一声根本发不出来**。

三次实测(每次都干净地只做一个动作):

| 测试 | 做了什么 | 服务器收到 |
|---|---|---|
| ① | 开小红书 → 停 20 秒 → 退回桌面 | 一条 `小红书`,**外加一条空的**(见下) |
| ② | 开小红书 → 直接切到抖音 | 只有 `小红书`,**没有抖音、没有空的** |
| ③ | 从桌面开抖音 → 停 20 秒 → 上划回桌面 → 再等 20 秒 | 只有 `抖音`,**中间什么都没有** |

**① 里那条「空的」记录差点让人下错结论**——它长得就像一次「关闭」(App 名为空,
因为那一刻前台已经是桌面了)。后来确认是**所有者自己在 Safari 里点了一下带 `?app=` 的排障网址**。
③ 是干净的复现,结论以它为准:**关闭不报**。

**教训有三条:**
1. **一次能对上的观测不算证据**,尤其当它正好符合你的预期。**换个动作再测一次**(② 和 ③ 就是这么把 ① 推翻的)。
2. **排障用的网址会污染数据**。给排障入口加个标记(或换个不写库的路径),别让它混进真实记录。
3. **「从后台切回 App」也可能不算「打开」**(② 里切到抖音就没报)。别假设 iOS 自动化的触发条件和直觉一致。

**所以别抄 toggle 方案**,用 1.5 那套「下一个 App 打开 = 上一个结束」的推法,
它**不需要手机端做任何改动**,也就没有「漏掉一次 close 导致状态永久反转」的隐患
(那正是 toggle 方案没写、但一定会咬人的地方)。

**顺带一个真实的阈值坑**:断段阈值(`STREAK_GAP_MIN`)第一版取 15 分钟,
结果她真实记录里一个 28 分钟的空档就把一整夜切成了碎段,**「已经连着玩了多久」当场归零**
——正好废掉这个功能最该抓的场景(盯着一个 App 不换)。**改成 30 分钟才对。**
同时注意别把「说不准」那句话的门槛复用同一个常量,否则一调阈值那句老实话会静默消失。

## 8. 急救开关与回滚

全套功能跑在 bridge 里,**AI 本体不依赖它**。就算整个炸掉,AI 照样聊天、照样有记忆和其他工具。

| 症状 | 一句话急救 |
|---|---|
| 查岗太吵 / 行为不对 | `CURFEW_ON=0` + 重启 bridge(只收上报不打扰) |
| 整套要停 | 删掉 `REPORT_TOKEN` + 重启(接口返回 503,自动化那边静默失败,手机无感) |
| bridge 整体不对 | 你系统里那个 bridge 总开关设 0,退回没有 Telegram 的状态 |

**如果上线后发现 AI 根本不用 `[查岗]` 标记**(这是这套设计已知的最大不确定性):
退路是改成「系统推给他」——门槛设成「她 N 分钟没说话 + 刚开过 App」。
**只改 bridge,不用重新部署 AI、不用她再归档一次**(前提是 2.4 那节措辞按建议写了)。
