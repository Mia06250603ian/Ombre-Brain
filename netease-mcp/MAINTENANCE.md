## 2. 源码从哪来、我们改了什么

上游 **[Vael-KY/netease-music-mcp](https://github.com/Vael-KY/netease-music-mcp) v3.1**(MIT),
它又重写自 `Cheiineeey/netease-music-mcp`。**我们是复制一份自己维护,不是 fork**
(所有者 2026-08-29 拍板;fork 的话 Actions 默认关那个坑还要再踩一次,见 `../browser-hands/MAINTENANCE.md` 踩坑 2)。
**代价:上游以后更新要手动搬**,搬的时候别把下面三处覆盖掉(`server.py` 里都标了「本地改动 A」,共 43 行)。

| 环境变量 | 线上现值 | 作用 |
|---|---|---|
| `MCP_TOKEN` | 已设(43 字符随机) | 请求必须带 `X-Token` 头。**不设 = 拒绝一切请求**(fail closed,照 gmail-mcp「白名单空=全拒」) |
| `WRITE_ENABLED` | **`1`** | 放开**可撤销**的四个:建歌单 / 塞歌 / 红心 / 改描述 |
| `DESTRUCTIVE_ENABLED` | **`0`** | **不可逆**的两个专用闸:`remove_from_playlist` / `reorder_playlist_tracks`。**开了写也照样拒绝** —— 网易云没有回收站 |
| `MAX_RESULT_CHARS` | `8000` | 单次工具返回字符上限。**这是为晏的窗口加的**,不是上游的功能 |
| `COOKIE_FILE` | 默认 `/data/netease-cookie.json` | 扫码拿到的凭证往这儿落。**没挂卷时写不进去,只在内存里** |
| `MCP_PORT` / `LOG_LEVEL` | `8080` / `INFO` | |

**五处本地改动**(`server.py` 里都标了「本地改动 X」):
**A** 鉴权 + 两道写闸 + 结果长度上限 / **B** 扫码登录(见第 4.5 节)/
**C** 修 `get_play_history`(上游线上恒 400)/ **D** 外部内容加壳 / **E** 红心列表补歌名。

**上游原版 `/mcp` 是零鉴权的** —— 谁知道网址谁就能操作账号,CORS 还是 `*`。
2026-08-29 实测确认过(不带任何 token 直接调用成功)。**所以这三个补丁不是优化,是上线前提。**

## 4.5 扫码登录(本地改动 B;**没有电脑也能续期**)

```bash
T=<MCP_TOKEN>   # 去 Zeabur 控制台看
curl -s -X POST https://yan-netease.zeabur.app/login/qr/new -H "X-Token: $T"
# → {"key": "...", "url": "https://music.163.com/login?codekey=..."}
# 把 url 生成二维码发给所有者 → 她用**网易云 app 扫一扫 → 相册选图 → 确认登录**
#   (同一部手机没法扫自己屏幕,所以要走「相册」那条路)
curl -s -X POST https://yan-netease.zeabur.app/login/qr/poll -H "X-Token: $T" \
     -H 'Content-Type: application/json' -d '{"key":"<上面那个 key>"}'
# 801=等待扫码 802=已扫待确认 803=成功 800=过期
```

⚠️ **必须走 weapi(加密接口),明文的不行。** 2026-08-29 实测,明文
`/api/login/qrcode/client/login` 在**沙箱和 Zeabur 两个 IP 上都**回
`code 8821「请切换其他登录方式或升级新版本再试」`(带 `anquanhuanjingfengxian` 的跳转链接);
同一时刻同一台机器,weapi 回 `801`。**判据就是 801 vs 8821。**
**服务只回状态,凭证不出容器。**

## 6. 踩过的坑

1. **⚠️ `zeabur variable create` 的退出码是骗人的。** 参数写错时 CLI 打 `ERROR` 但
   **npx 仍然退出 0**,循环里五个变量全没设进去、日志上一片「退出码 0」。
   2026-08-29 就是这么栽的,靠**回读键名**才发现。
   **规矩:设完变量必须回读一次键名对账,永远别信退出码。**
   正确语法是 `-k KEY=VALUE`(一体),**没有 `--value` 这个 flag**。
2. **`variable create` 会把整张变量表连值一起打出来**(2026-08-28 记在 OPERATIONS 第 0 节第 6 条)。
   本次做法:`> /tmp/xxx.log 2>&1` 全部重定向,只 `grep -i error` 看报错行,
   回读用 `--json` + node 只打印 key 名。**值一次都没进会话记录。**
3. **本沙箱里 `zeabur deployment list` 被权限分类器拦掉**(2026-08-29 连试两次)。
   PLANTYPE 那条规矩(shim 踩坑 17)因此没法照原样执行。
   **替代做法**:用 `service get` 看 STATUS,再用**功能验收**(第 5 节那八条)证明它真在跑
   ——功能过了比 PLANTYPE 对了更有说服力。下次若能跑 `deployment list`,照旧先看 PLANTYPE。
4. **⚠️ `variable create` 撞上已存在的键会失败,要用 `variable update`。**
   2026-08-29 第二次栽在变量上:`create` 回 `variable WRITE_ENABLED already exists`,
   **而回读发现值还是旧的 `0`**。**又是靠回读才发现的** —— 和坑 1 同一个教训。
   `update` 的参数和 `create` 一样是 `-k KEY=VALUE`,并且**要 `-i=false`**(否则进交互模式,
   脚本里 EOF 报错;这条 chess-web 第一次部署也记过)。

5. **`zeabur service exec` 撑不住长连接,约 3 分钟就被网关掐断(524)。**
   2026-08-29 想在容器里跑一个轮询循环等扫码,回
   `execute command failed: Message: 524`。**exec 只适合打完就走的短命令**,
   要轮询就在本地循环、每次 exec 一枪,或者干脆做成服务自己的端点(本次就是这么解决的)。

6. **`pkill -f "<关键词>"` 会把发起它的那条 bash 自己杀掉**(命令行里含同样的关键词)。
   2026-08-29 连栽两次,表现是**整条命令退出码 144、后半段静默不执行**。
   **改用 `$!` 记 PID 再 `kill`,别用 pkill 匹配。**

7. **构建方式锁死成 dockerfile,别让平台猜。** 这个服务是「单个 `.py` + 没有 requirements.txt」,
   zbpack 的探测结果不可预期。仓库里放了 6 行 `Dockerfile` + `zbpack.json`(`build_type: dockerfile`),
   照根目录 OB 的做法。**沙箱里有 docker 命令但没有 daemon,镜像没能在本地构过**,
   是直接在 Zeabur 上构的 —— 可接受,因为构建失败是响亮的,不会静默带病上线。
