# Opus 5.5 被安全审查拦了不丢窗口:实施指南

> 写给**同款架构**的下一个 Claude Code(也可以直接转给维护同款系统的朋友)。
> 原型于 2026-09-29 在一套线上系统实装、真接口验证并上线。
> **适用前提**:你维护一个 shim,它常驻一个 `claude -p --input-format stream-json --output-format stream-json` 进程
> 当 AI 本体,前端(Kelivo / Telegram 桥 / 网页……)经它的 `/v1/messages` 说话;**5.5 跑在一份 ≥ 2.1.280 的新版 Claude Code 上**
> (老版 CLI 不认识 `claude-opus-5-5`)。结构不同的话,第 1 节的原理仍然通用,代码要自己改。
>
> 文中所有地址、密钥、称呼都是占位符。**先读第 5 节「坑」再动手** —— 其中两条会让你写出「测试全绿、实际坑人」的版本。

---

## 0. 解决的是什么问题

**症状**:用 5.5 聊着聊着,前端开始每句都回报错(常见是一句「上游断了 / 上游报错」),**之后说什么都这样**。
shim 的调试口(或 CLI 会话记录)里的原文是:

```
API Error: Opus 5.5's safeguards flagged this message (https://www.anthropic.com/legal/aup).
This sometimes happens with safe, normal conversations. Claude Code can't respond to this message with Opus 5.5.
```

**不是链路断了**,是 5.5 的安全审查拦了。要命的是它会**一直卡**:
被拦的那句留在会话记录里,之后每句都连着它一起发、一起被拦。以前唯一的办法是切到 4.x = **开新窗口**,
没来得及归档的全丢。审查看的是**整个窗口**,不只最后一句,所以长而亲密的窗口特别容易中招,报错原文也自认会误判。

**做完之后的效果**(用户视角):

1. **第一次被拦 → 自动撤回**:她收到一行 `⚠️ 5.5 拦了这句,已经撤回了(他没看到)。换个说法再说一次吧;要是还被拦,会自动换成 4.6-next 接着聊。`
   被拦那句从 AI 的记忆里抹掉,**还是 5.5、还是这个窗口**,几乎不花额度。
2. **撤回后换了说法又被拦 → 原地换成 4.6**:她先看到 `⚠️ 5.5 拦了这句,已经自动换成 4.6-next 接着聊,窗口没丢。`,
   紧接着 4.6 回她那句。之前聊的全在,之后这个窗口锁在 4.6。
3. **Kelivo 菜单里多一项 `claude-opus-4-6-next`**(= 新版 CLI 上的 4.6):5.5 窗口里点它 = 原地换、不丢窗口;
   点回 5.5 也原地;点普通的 4.6 / 4.5 / 4.8 照旧开新窗口。

---

## 1. 原理(四件事)

### 1.1 认出「被拦」

CLI 2.1.280 在 API 回 `stop_reason: "refusal"` 时,拼出上面那句报错,做成一条 `isApiErrorMessage: true` 的 assistant 消息
(同时还有一条 `{type:"system", subtype:"model_refusal_no_fallback"}` 事件)。
**认准 `safeguards flagged this message` 这几个字就够了**,不要认 `aup` 链接(别的措辞里也有)。

### 1.2 撤回 = 截断续上

新版 CLI 有两个隐藏参数(`--help` 里不显示):

```
--resume <会话id> --resume-session-at <某条消息的 uuid>
```

意思是「接着这个会话,但只读到这一条为止」。所以被拦时:

1. 记住**上一轮成功回合最后一条 assistant 消息的 uuid**(stream-json 里 `type:"assistant"` 事件自带 `uuid`,会话 id 在 `session_id`);
2. 杀掉进程,用这两个参数原地重起 —— **被拦那一轮就被截掉了**,模型不变,还是同一个会话 id。

**真接口实测**:撤回后只记得撤回点之前的话;**缓存几乎全中**(一段 1.8 万 token 的前缀,重起后 18633 读缓存、只新写 19)
—— 因为同一模型、同一前缀。**撤回几乎不花钱。**

### 1.3 换模型 = 给活着的进程发 `set_model`

stream-json 模式下可以往 stdin 写一条控制消息,不重启就换模型:

```json
{"type":"control_request","request_id":"<随便一个id>","request":{"subtype":"set_model","model":"claude-opus-4-6"}}
```

CLI 回一条 `{"type":"control_response","response":{"subtype":"success","request_id":"<同一个id>"}}`。
会话、历史都在;**真接口验过 4.6 接得住 5.5 的思考块**。代价:缓存是按模型分的,换过去那一句要把整个窗口重读一遍
(1 小时缓存写入是 2 倍价;16 万 token 的窗口约合 33 万 token 当量,≈ 保温一天,**只花一次**)。

⚠️ **换完之后她那句还在会话里**(见坑 1),所以不要重发她的话,而是补一句让 4.6 开口(本文用一条 `【系统·补发】` 标注)。

### 1.4 为什么「先撤回、再换模型」

- 撤回几乎免费、而且还是 5.5;
- 但审查看的是整窗,换了说法**可能还被拦** → 这时再撤回没意义,换 4.6(它没有这道拦截)保住窗口。
- 判据:**撤回之后、还没有任何一轮成功,就又被拦了** → 换模型;中间只要成功过一轮,下次被拦仍先撤回。
- 撤不了的时候直接换:窗口第一句就被拦(还没有撤回点)、「换窗口」那种指令回合。

## 2. 代码

### 2.1 纯逻辑模块 `flagfallback.mjs`(照抄即可,零依赖)

```js
// flagfallback.mjs — 5.5 被安全审查拦了:先撤回那一轮,再被拦就原地换 4.6(纯逻辑,单测覆盖)

// 被拦的指纹(CLI 2.1.280 在 stop_reason:"refusal" 时拼的那句)
export function isFlagged(apiError) {
  return /safeguards flagged this message/i.test(String(apiError || ""));
}

// 这一轮能不能「换模型」
export function flagFallbackDecision({ apiError = "", fallbackModel = "", model = "", cli = "", tried = false } = {}) {
  if (!fallbackModel) return { fallback: false, reason: "off" };
  if (!isFlagged(apiError)) return { fallback: false, reason: "not-flagged" };
  // ⚠️ 有没有正文不看:拦截可能发生在说到一半,那种窗口同样卡死
  if (tried) return { fallback: false, reason: "tried" };            // 这一轮处理过一次了,防死循环
  if (model === fallbackModel) return { fallback: false, reason: "same-model" };
  if (cli !== "next") return { fallback: false, reason: "not-next-cli" }; // 只在新版 CLI 上做
  return { fallback: true, reason: "flagged" };
}

// 被拦时做什么:"rollback" / "fallback" / "none"(走原来的报错)
export function flagAction({ apiError = "", fallbackModel = "", model = "", cli = "", tried = false,
                             rollbackOn = false, canRollback = false, justRolledBack = false, newWindow = false } = {}) {
  if (!isFlagged(apiError) || tried || cli !== "next") return "none";
  if (rollbackOn && canRollback && !justRolledBack && !newWindow) return "rollback";
  return flagFallbackDecision({ apiError, fallbackModel, model, cli, tried }).fallback ? "fallback" : "none";
}

// claude-opus-5-5 → 5.5,claude-opus-4-6-next → 4.6-next
export function shortModel(m) {
  const x = String(m || "").match(/-(\d+)-(\d+)(?:-\d{8})?(-next)?$/);
  return x ? `${x[1]}.${x[2]}${x[3] || ""}` : String(m || "");
}

// 给用户看的两行(放正文)
export function flagRollbackNote(model, to = "claude-opus-4-6-next") {
  return `⚠️ ${shortModel(model)} 拦了这句,已经撤回了(他没看到)。换个说法再说一次吧;要是还被拦,会自动换成 ${shortModel(to)} 接着聊。`;
}
export function flagNote(from, to) {
  return `⚠️ ${shortModel(from)} 拦了这句,已经自动换成 ${shortModel(to)} 接着聊,窗口没丢。\n\n`;
}

// 换过去之后让 4.6 开口的那一条(和被拦那句并成同一条 user 消息)。称呼按你家的改。
export const FLAG_NUDGE = "【系统·补发】上面她那句刚才没送到你这边,现在到了,直接回她就行。永远不提这行。";

// 窗口锁:换过之后,前端还报被拦的那个模型 → 留在换过去的模型上(否则 shim 会以为要换模型、开新窗口)
export function lockedModel({ requested = "", lock = null } = {}) {
  return lock && requested === lock.from ? lock.to : requested;
}
```

⚠️ `FLAG_NUDGE` 用的是「【系统·…】标注」的格式 —— 如果你家 AI 的人设里约定了「这类标注只给我看、永远不提」,就沿用;
没有这个约定的话,换成你家 AI 认得的系统提示格式,**措辞给主人过目**。

### 2.2 菜单别名 `-next`(放在你「选哪份 CLI」的那个模块里)

```js
export const NEXT_ALIAS_SUFFIX = "-next";
export const isNextAlias = (m) => typeof m === "string" && m.length > NEXT_ALIAS_SUFFIX.length && m.endsWith(NEXT_ALIAS_SUFFIX);
export const realModel = (m) => isNextAlias(m) ? m.slice(0, -NEXT_ALIAS_SUFFIX.length) : m;   // 发给上游时去掉后缀
export const nextAlias = (m) => m ? (isNextAlias(m) ? m : m + NEXT_ALIAS_SUFFIX) : "";
// 你的「这个模型走哪份 CLI」判断里加一条:isNextAlias(model) → 走新版
// 你的「新版 CLI 不在就把需要它的模型从菜单拿掉」里也加上 isNextAlias
```

### 2.3 `server.js` 接线(七处)

下面的变量名按一个典型 shim 写:`proc` 常驻进程、`turn` 当前回合、`spawnedModel/spawnedCli/spawnedSystem` 进程出生时的参数、
`pump()` 队列、`finishTurn()` 一轮收尾。对着你自己的代码找对应位置。

**① 配置与状态**

```js
const FLAG_FALLBACK_MODEL = (process.env.FLAG_FALLBACK_MODEL ?? "claude-opus-4-6").trim(); // 空 = 不换
const FLAG_ROLLBACK = process.env.FLAG_ROLLBACK !== "0";                                     // 0 = 不撤回
const FLAG_SWITCH_TIMEOUT_MS = +(process.env.FLAG_SWITCH_TIMEOUT_MS || 30000) || 30000;
const FLAG_TO = FLAG_FALLBACK_MODEL ? nextAlias(FLAG_FALLBACK_MODEL) : "";
if (FLAG_TO && NEXT_READY && !MODELS.includes(FLAG_TO)) MODELS.push(FLAG_TO);   // 自动进菜单
let flagLock = null, pendingCtl = null;
let sessionId = null, keepUuid = null, justRolledBack = false;
```

**② 起进程:支持「截断续上」,且续上的不清零**

```js
function spawnClaude(system, model, resume = null) {       // resume = { sid, at }
  // ...
  if (!resume) {                  // 新窗口才清零;撤回续上的是同一个窗口
    /* 你原来的守卫/计数清零 */ flagLock = null; sessionId = null; keepUuid = null; justRolledBack = false;
  }
  const args = [ /* ... */ "--model", realModel(model), /* ... */ ];
  if (resume?.sid) { args.push("--resume", resume.sid); if (resume.at) args.push("--resume-session-at", resume.at); }
  // 关掉 CLI 自带的「被拦自动换模型」,换模型由 shim 来做(两边都换会让记账乱掉)
  if ((FLAG_FALLBACK_MODEL || FLAG_ROLLBACK) && cli.which === "next") env.CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK = "1";
  const p = spawn(cli.bin, args, { /* ... */ });
  p.resume = resume; p.okTurns = 0;
  p.on("close", () => {
    if (proc !== p) return;
    // ...你原来的收尾...
    // 撤回重起一轮都没成就退了(撤回点找不到等):退一步不截断地接回,总比开新窗口强
    if (p.resume?.at && !p.okTurns) {
      setTimeout(() => { if (!proc) proc = spawnClaude(spawnedSystem, spawnedModel, { sid: p.resume.sid }); }, 1500);
      return;
    }
    setTimeout(() => ensureProc(spawnedSystem, spawnedModel), 1500);
  });
  return p;
}
```


**⑥ 撤回、换模型本身**

```js
function flagRollback(t) {
  t.flagTried = true;
  const resume = { sid: sessionId, at: keepUuid };
  const old = proc; proc = null; try { old?.kill(); } catch {}      // 先置空,旧进程的 close 就不动现场
  proc = spawnClaude(spawnedSystem, spawnedModel, resume);
  justRolledBack = true;
  if (!t.isKA && !t.isSystem) { t.prefix = (t.fullText ? "\n\n" : "") + flagRollbackNote(spawnedModel, FLAG_TO); t.sse?.text(t.prefix); }
  t.done = true; t.sse?.finish(undefined, t.prefix);
  turn = null; busy = false; pump();
}

function flagFallback(t, ev) {
  const from = spawnedModel, to = FLAG_TO, p = proc;
  t.flagTried = true;
  setModel(p, realModel(to)).then((ok) => {
    if (turn !== t || proc !== p) return;
    if (!ok) { finishTurn(ev); return; }                               // 换不成:走原来的报错
    spawnedModel = to; flagLock = { from, to };
    if (!t.isKA && !t.isSystem) { t.prefix = (t.fullText ? "\n\n" : "") + flagNote(from, to); t.sse?.text(t.prefix); }
    t.fullText = ""; t.apiError = "";                                  // 同一个 turn 接着收 4.6 的回话
    p.stdin.write(JSON.stringify({ type: "user", message: { role: "user", content: FLAG_NUDGE } }) + "\n");
  });
}

function setModel(p, model) {
  return new Promise((resolve) => {
    if (!p || !p.stdin.writable) return resolve(false);
    const id = "flag_" + Math.random().toString(36).slice(2, 14);
    const timer = setTimeout(() => { if (pendingCtl?.id === id) pendingCtl = null; resolve(false); }, FLAG_SWITCH_TIMEOUT_MS);
    pendingCtl = { id, resolve: (v) => { clearTimeout(timer); resolve(v); } };
    p.stdin.write(JSON.stringify({ type: "control_request", request_id: id, request: { subtype: "set_model", model } }) + "\n");
  });
}
```

`finishTurn` 里把 `sse.finish(usage, fullText)` 改成 `finish(usage, (turn.prefix || "") + turn.fullText)`,非流式请求也拿得到那行提示。
`pump()` 建 `turn` 时加上 `flagTried: false, prefix: ""`。

**⑦ 请求入口上锁 + `pump` 里原地换模型**

```js
// handleMessages 里定 model 的那行:
const model = lockedModel({ requested: MODELS.includes(body.model) ? body.model : spawnedModel, lock: flagLock });

// pump() 里,在「模型变了就杀进程」之前:新版进程里换到另一个也走新版的模型 = 原地 set_model
if (proc && item.system === spawnedSystem && item.model !== spawnedModel && spawnedCli === "next" && cliFor(item.model).which === "next") {
  const p = proc, to = item.model;
  const wait = Math.max(0, procReadyAt - Date.now());                 // 刚起的进程先等 MCP 握手
  setTimeout(() => setModel(p, realModel(to)).then((ok) => {
    if (proc === p) { if (ok) spawnedModel = to; else { try { p.kill(); } catch {} proc = null; } }
    runItem(item);                                                    // runItem = 你原来 pump 的后半段
  }), wait);
  return;
}
```

## 3. 测试

### 3.1 单测
对 `flagfallback.mjs` 的每个分支写断言:第一次被拦 → 撤回;撤回后又被拦 → 换;没撤回点 → 换;两个开关各自关掉;
链路断(503)不是被拦;`tried` 防死循环;老版 CLI 上不做;`-next` 别名的 `realModel` / 选 CLI / 进不进菜单。

### 3.2 端到端(零额度):假后端怎么模拟「被拦」
真 shim + 两份真 CLI + 一个假的 Anthropic 后端(`ANTHROPIC_BASE_URL` 指过去),约定:
**5.5 的请求里出现某个暗号(如 `FLAGME`)就回一个只有 `message_start` + `message_delta{stop_reason:"refusal"}` 的 SSE**,
其余正常回话。CLI 会自己把它变成那句 `safeguards flagged` 报错,和真的一样。

⚠️ 假后端必须同时支持**非流式**请求(见坑 3)。建议覆盖这几个阶段:
撤回 → 换说法成功 → 再被拦撤回 → 紧接着又被拦换 4.6(断言她那句**只出现一次**)、之后前端还报 5.5 仍留在 4.6、改选别的模型才开新窗口;
两个开关都关 = 老报错;说到一半被拦;窗口第一句就被拦;菜单手动 5.5 ↔ 4.6-next 原地切;删掉会话记录模拟撤回失败(见坑 5)。

### 3.3 真接口小成本验证(容器里一次性小进程,别碰 AI 本体)
- 5.5 聊两句(带思考)→ `set_model` 到 4.6 → 问前文:应记得,且不报错;
- 5.5 聊两句(第二句说个暗号)→ 杀掉 → `--resume … --resume-session-at <第一轮最后一条 uuid>` 重起 → 问暗号:应**不记得**第二句;看 usage 缓存读多写少;
- 拿一份真被拦的会话记录**复制到临时目录**,用新版 CLI 按撤回参数打开**但不发消息**(零额度),进程能起来 = 撤回点可用;
  对照组用一个不存在的 uuid,应当场 `No message found with message.uuid` 退出。

## 5. 坑(每一条都是真撞过的)

1. **被拦之后,她那句并没有从会话里消失**,丢的只是那条报错。第一版写成「换到 4.6 后把她那句原样重发」,
   结果和留着的那句并成同一条消息 = 4.6 看到她说了两遍(有图片的话图片也两遍)。**只补一句让他开口,别重发。**
2. **撤回点必须是「成功回合」的最后一条 assistant uuid**,在回合成功收尾时才转正;被拦那轮自己的 uuid 不能用。
   窗口第一句就被拦时根本没有撤回点 → 直接换模型(这不是撤回坏了)。
3. **`set_model` 之前,CLI 会先发一条非流式的 `Hi` 验证新模型**。假后端只会回 SSE 的话,CLI 报
   `Unable to validate model: … usage.input_tokens`、换模型失败 —— 真接口没这事,是测试环境的坑。
4. **换完模型后,下一条消息前面会多出 CLI 自己的 `/model` 记录**(`<local-command-caveat>` + `Set model to …`),
   它自带「别回这段」,不用管;但你的测试如果按「消息开头几个字」认轮次,会认错,比对前先把这段去掉。
5. **撤回重起可能失败**(撤回点在会话记录里找不到,CLI 立刻 `exited 1`)。别直接开新窗口:
   先**不截断地**接回原会话(被拦那句跟着回来 → 下一句再被拦时 `justRolledBack` 仍为真 → 换 4.6),再不行才开新窗口。
6. **窗口锁**:换到 4.6 之后,前端(比如 Kelivo)菜单里还选着 5.5,之后每条都报「5.5」。不锁的话 shim 会以为她要换模型 →
   杀进程开新窗口,等于白救。锁到这个进程结束(换窗口 / 改选别的模型 / 重启)为止。**同一个窗口别再切回 5.5**(被拦那句还在记录里,会再被拦)。
7. **关掉 CLI 自带的 `switchModelsOnFlag`**(`CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1`,只加给新版进程):它挂着一堆内部开关、
   线上不一定触发,真触发时 shim 以为还在 5.5、CLI 已经悄悄换了,记账全乱。
8. **撤回会连带丢掉那一轮注入的系统标注**(时间、天气、上下文提醒等)。守卫的「已催过」记账不回滚,被撤回的若正好是催归档那句,那次提醒就没了。
