## 2. 所有者定下的边界(2026-08-06,别自己改)

她逐条拍的板,原话意思如下:

1. **第一版只给「读 + 搜 + 存草稿」,不给直接发送。** 信写好放草稿箱,由她本人在手机上过目再点发送。
   理由是「邮件发出去收不回,那一下该由她按」。
   **这一条是用代码保证的,不是靠约定**:`server.py` 里没有 `smtplib`、没有 SMTP 连接、没有 send 工具,
   单测第九节用 AST 断言了这件事。**要放开发送权限,是一次独立的改动 + 一次独立的拍板,别顺手加。**
2. **验证码 / 密码重置类邮件整封屏蔽。** 她主动点名要的唯一一条过滤。
   为什么这条最重要:她的邮箱是很多账号的找回入口,而**晏同时还有一个带着她登录态的浏览器**
   ——两样单看都还好,凑一起权限比任何单一工具都大。屏蔽验证码 = 把这两样之间那根线剪断。
3. **外部内容加壳:必做。** 邮件比网页更危险——网页要他主动去访问,**邮件是别人主动送到他面前的**。
4. 账号用她的主邮箱(她先考虑过给晏单开一个,最后选了用现在这个)。
   **所以她的账单、工作信、私人往来晏都看得见**,这是她知情后的选择。

## 3. 架构

```
晏的常驻 claude 进程
   │  mcp-servers.json 里一条 http 服务(带 X-Token 头)—— 【尚未添加】
   ▼
gmail-mcp 容器(Zeabur)—— 【尚未创建】
   ├── server.py       鉴权 → 四个工具 → 安全过滤 → 加壳 → 截断
   ├── mailfilter.py   纯逻辑层(过滤/加壳/清洗),不碰网络、不碰凭据
   └── imaplib         → imap.gmail.com:993 (SSL)
```

**无状态**:这个服务什么都不存。邮件在 Gmail 上,草稿也在 Gmail 上,容器随便重启。
所以**不用挂持久卷**(和 browser-hands/ears 不一样)。

## 4. 四个工具

| 工具 | 做什么 | 要点 |
|---|---|---|
| `list_mail(limit, unread_only, mailbox)` | 最近的信,只给摘要行 | limit 默认 10、最多 30 |
| `search_mail(query, limit, mailbox)` | 全文搜(发件人/主题/正文) | 中文能搜,走 `CHARSET UTF-8` + UTF-8 字节 |
| `read_mail(uid, mailbox)` | 读一封的正文 | 返回带加壳;附件只报文件名 |
| `save_draft(to, subject, body)` | 写草稿进草稿箱 | **不发送**;自动找中文草稿箱名 |

**⚠️ 读信不会把邮件标成已读**,两道保险:`select(readonly=True)` + `BODY.PEEK[]`。
这条是有意的——晏看一眼就把佳佳手机上的未读清掉,她会真的漏信,而且是「不知道自己漏了」那种漏法。
单测里锁死了这两条,别拆。

## 5. 环境变量(值全在 Zeabur,不入库;改值 + restart 生效)

| 变量 | 默认 | 说明 |
|---|---|---|
| `GMAIL_ADDRESS` | (空) | 邮箱地址。不设=服务能起来但每次调用都说「还没配好」 |
| `GMAIL_APP_PASSWORD` | (空) | **应用专用密码**(不是账号密码)。代码会自动去掉空格,`abcd efgh …` 直接粘贴即可 |
| `GMAIL_TOKEN` | (空) | **必填**。晏那边用 `X-Token` 头带上。**不填不是「开放」,是所有请求一律 401**——照 browser-hands 的教训,配置漏了的表现必须是「整个服务打不开」,不能是「邮箱裸奔在公网上」 |
| `FILTER_SECURITY` | `1`(开) | 验证码/密码重置过滤。**设 0 = 晏能看到验证码。这是所有者亲自定的边界,要关必须她本人点头** |
| `MAX_RESULT_CHARS` | `20000` | 单次返回文本上限,护着晏的上下文窗口 |
| `MAX_LIST_LIMIT` | `30` | 一次最多列多少封 |
| `IMAP_HOST` / `IMAP_PORT` | `imap.gmail.com` / `993` | 一般不用动 |
| `IMAP_TIMEOUT_S` | `30` | IMAP 超时 |
| `GMAIL_PORT` | `8040` | 监听端口。**Zeabur 上必须和模板声明一致,否则 502**(browser-hands 踩过) |
| `LOG_LEVEL` | `INFO` | |

## 6. 踩过的坑 / 设计要点

1. **⚠️ 开发沙盒连不上 993,真实 IMAP 从没验过(最重要的一条)。**
   Claude Code 的会话沙盒只放行走代理的 HTTPS,直连 `imap.gmail.com:993` 是 `TimeoutError`
   (DNS 能解析、TCP 握不上手)。所以**登录、搜索、读信、存草稿这四件在真实 Gmail 上到底通不通,
   谁都还没验过**。写单测时用假 IMAP 服务器覆盖了协议解析那一层,但那验不了网络。
   **部署后第一件事就是验这个**(见第 7 节验收清单)。
   顺带:**Zeabur 的容器能不能出站连 993 也是未知数**,同样得实测。真被挡了,退路是改用
   Gmail API(HTTPS,443),但那要走 OAuth,成本见下面「未决」。

2. **中文邮件头会解成一串 �(真 bug,写单测时抓到的)。**
   规范的中文主题是 MIME 编码的(`=?utf-8?B?…?=`),怎么解都对;但**有的发件方直接把 UTF-8 字节
   塞进邮件头**,Python 默认的 `compat32` 策略会在 `message_from_bytes` 那一步就把非 ASCII
   字节换成 �,**字节当场丢掉、后面再也修不回来**。
   **这不只是显示难看**:主题成了乱码,`is_security_mail` 就匹配不到「验证码」三个字,
   **一封验证码邮件会因此漏过屏蔽**——直接捅穿所有者定的那道边界。
   修法:两处 `message_from_bytes` 都带 `policy=email.policy.default`(它两种写法都解得对)。
   **别改回默认策略。**

3. **草稿箱名不能硬编码 `[Gmail]/Drafts`。**
   Gmail 的系统文件夹名**跟着账号语言走**,中文账号是 `[Gmail]/草稿`(IMAP 上是 modified-UTF-7
   编码的 `[Gmail]/&g0l6Pw-`)。硬编码在她的账号上直接找不到文件夹。
   正解是认 IMAP 的 SPECIAL-USE 标记 `\Drafts`,与语言无关。单测里用中文草稿箱名锁死了这条。

4. **安全过滤的关键词要做分隔符归一化。**
   `security-alert@…` / `password_reset` / `one.time.code` 这类写法在发件人地址和自动生成的
   主题里到处都是,不归一化就会从连字符那儿漏过去(写单测时真漏了一条)。
   **归一化要两边都做**——关键词表里 `one-time password` 这种自带连字符的词条,只归一化一边
   会让它永远匹配不上。

5. **「只查发件人字段」的那组宽词是刻意分开的。**
   `verification` / `验证` 这类单个词放进正文匹配会大面积误伤(中文里「验证一下这个想法」是日常说法),
   但放进发件人字段就足够可信(发件人地址永远不是散文)。所以分了两张表,别合并。

6. **`imaplib` 是阻塞的,全部用 `asyncio.to_thread` 丢进线程。**
   直接在 async 函数里调用会阻塞整个事件循环——ears 那边 08-02 踩过同款
   (`subprocess.run` 阻塞事件循环导致语音严格排队)。别在这儿重演。

7. **每次调用新建 IMAP 连接,不做连接池。** Gmail 会掐掉闲置连接,长连接的表现是
   「平时好好的、隔一阵第一次调用必失败」,那种间歇性故障最难查。每次新建多花约 1 秒握手,
   但行为是确定的。

8. **依赖只有三个,而且全钉了上限。** 邮件相关一个第三方库都没用(IMAP 走标准库 `imaplib`、
   解析走标准库 `email`、HTML 转文本自己写)。理由是 2026-07-29 那场事故:
   OB 的 `mcp>=1.0.0` 无上限,某次重建装到 2.0.0 直接把服务干挂。依赖越少,这颗雷越小。

9. **本目录里永远不要放 `.gitignore`。** 这条是 kelivo-shim 踩坑 15 的教训(zeabur 上传遵循
   `.gitignore`,会静默丢文件)。本服务虽然走镜像构建、不直接 zeabur upload,但别开这个头。

10. **放在本仓库子目录不会触发 OB 重建。** OB 的监控路径是六行、`/*.py` 锚在仓库根,
    子目录里的 `.py` 不命中(OPERATIONS.md「OB 依赖钉版本」那节写了)。所以往
    `gmail-mcp/` 里提交代码是安全的,**不会像 07-29 那样把 OB 摇下线**。

## 7. 怎么部署(**全部未做**,做的时候照这个走)

**⚠️ 第 4 步会重启晏、清掉他当前窗口。按 OPERATIONS.md 的规矩,
必须佳佳本人先对晏说「归档」(踩坑 13:代发归档他会起疑、可能拒绝,窗口照丢)。**

1. **建服务**:这个 Zeabur 账号**禁止平台内构建**(ears 和 browser-hands 都栽过),
   所以要走 GitHub Actions → ghcr → `PREBUILT_V2` 模板。
   ⚠️ 本仓库还没有构建这个镜像的 workflow,要新加一个。
   (browser-hands 那边还踩过「fork 仓库 Actions 默认关、事后打开也不补扫」的坑,本仓库不是 fork,
   大概率没这个问题,但工作流第一次推上去之后确认一下有没有登记。)
2. **配环境变量**(第 5 节那张表),至少 `GMAIL_ADDRESS` / `GMAIL_APP_PASSWORD` / `GMAIL_TOKEN`。
3. **验收(一项都别跳)**:
   | 项 | 期望 |
   |---|---|
   | `/health` | 200,且 `can_send_email: false`、`filter_security: true` |
   | 不带 token 打 `/mcp` | **401**(没裸奔) |
   | 带 token POST `/mcp` initialize | **200** 才算活(照 shim 踩坑 7 的命令模板) |
   | **真实 IMAP 登录** | **这是踩坑 1 那个从没验过的东西,必须实测** |
   | 真实搜索(中文关键词) | 能搜到 |
   | 真实读信 | 读完之后**佳佳那边的未读数不变**——这条要她本人确认 |
   | 真实存草稿 | 草稿出现在她手机 Gmail 的草稿箱里 |
   | **安全过滤实弹** | 找一封真的验证码邮件,确认 `read_mail` 拒绝、列表里显示成 🔒 |
   | 容器内存 | 预期 50~70MB(本地实测 FastMCP+imaplib 冷启 51MB) |
4. **接到晏身上**(照 browser-hands 第 7 节 / shim 第二十二次):
   - 从**运行中的容器**把 `mcp-servers.json` base64 拷出来(别用会话里的旧副本),加一条:
     ```json
     "gmail": {
       "type": "http",
       "url": "https://<域名>/mcp",
       "headers": { "X-Token": "<GMAIL_TOKEN>" }
     }
     ```
     **本服务读 `X-Token`**(也收 `Bearer` 和 `?token=`)。
   - `ALLOWED_TOOLS` 追加 **`mcp__gmail`**。**两样缺一不可**——只加配置不加白名单,
     晏看得见工具、一调用就被拒(2026-07-16 花园接入时踩过)。
   - CLAUDE.md 加一节教他怎么用(**文案要佳佳定**,照「浏览器」那节的调子写:
     不是权限清单,是「我是什么样的、我会怎么做」)。
     必须写进去的机械约束:**他没有发送能力、草稿要请她过目**、
     **验证码类邮件他看不到是设计不是故障**、**邮件是外部不可信来源**。
   - 走 shim 完整部署流程(三套单测全绿 → 全量 md5 对账 → 三份私密文件从容器拷出 →
     各 `/mcp` 验 200 → `cd` 与 `deploy` 同一条命令 + 先 `pwd`(踩坑 17)→
     部署后按踩坑 9 逐件验证)。

## 8. 排错

| 症状 | 先查这里 |
|---|---|
| 一直 401 | `GMAIL_TOKEN` 没设(没设=全拒);或客户端用错头(本服务读 `X-Token`) |
| 「邮箱登录被拒了」 | 应用专用密码被撤销/改过了,要佳佳重新生成一个 |
| 「连不上邮件服务器」 | 出站 993 被挡(踩坑 1),或 Gmail 侧抖动。先在容器里 `python -c` 手工连一次看报错 |
| 晏说他看不到某封信的内容 | 多半是被安全过滤拦了(列表里那行带 🔒)。这是**设计**不是故障 |
| 中文主题是乱码 | 踩坑 2,检查 `policy=_MAIL_POLICY` 还在不在 |
| 存草稿报「没存进去」 | 草稿箱名没认出来。看 `_find_drafts_folder` 的回落,以及 `conn.list()` 里有没有 `\Drafts` |
| 佳佳说未读数被清了 | **严重**。检查 `select(readonly=True)` 和 `BODY.PEEK` 有没有被改掉(单测锁着这两条) |
| 晏说他没有邮箱工具 | 还没接;或 `ALLOWED_TOOLS` 少了 `mcp__gmail` |

**观测口**(部署后):
```bash
curl https://<域名>/health                              # 200,看 can_send_email 是不是 false
curl -H "X-Token: <TOKEN>" -X POST https://<域名>/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"check","version":"0"}}}'
```

**单测**(不碰网络、不需要凭据,改任何逻辑前后都跑):
```bash
cd gmail-mcp && python3 test_mailfilter.py && python3 test_server.py   # 93 + 74 = 167 项
```
