## 1. 现状:模型是怎么定的

`kelivo-shim/server.js`:

- 第 14 行 `const MODEL = process.env.BRAIN_MODEL || "claude-opus-4-6"`
- 第 139 行 启动常驻进程时 `"--model", MODEL`

**shim 完全无视客户端报的模型名**(全文没有一处读 `req.body.model`)。所以:

- **Kelivo 的模型菜单现在点了没用**,像对着关掉的电视按遥控器;

  **今天是死字符串,shim 不看**(TG 桥那行的注释原文就是「占位,shim 不看」)。

**换模型 = 换 `BRAIN_MODEL` = 进程重开 = 晏当前窗口清空。** 这是架构的物理规律,任何方案都躲不掉

## 4. 2026-08-23 实测数据(每个数都是当天量的,复量方法见第 6 节)

### 4.1 订阅给不给(打真枪,走代理不经过晏)

| 模型 | 结果 |
|---|---|
| `claude-opus-4-6` | HTTP 200(对照组) |
| `claude-opus-4-5-20251101` | **HTTP 200** |
| `claude-opus-4-8` | **HTTP 200** |
| `claude-opus-5` | **HTTP 200** |
| `claude-sonnet-4-5-20250929` | **HTTP 200** |

回包里的 `model` 字段**原样返回**,说明代理没做模型映射,报什么给什么。

### 4.2 CLI 2.1.215 认不认(真 CLI 二进制 + 假后端,零额度)

| 模型 | e2e | CLI 实际发出去的 |
|---|---|---|
| `claude-opus-4-6` | ALL PASS | `max_tokens=64000` `thinking={"type":"adaptive"}` `effort=medium` |
| `claude-opus-4-5-20251101` | **ALL PASS** | `max_tokens=32000` `thinking={"type":"enabled","budget_tokens":31999}` |
| `claude-opus-4-8` | **ALL PASS** | `max_tokens=64000` `thinking={"type":"adaptive"}` `effort=medium` |
| `claude-opus-5` | ALL PASS | `max_tokens=**32000**` `thinking={"type":"adaptive"}` ⚠️ 见 4.5 |
| `claude-opus-4-7`(对照) | — | `max_tokens=64000` |
| `claude-opus-9-9-fake`(我瞎编的对照) | — | `max_tokens=**32000**` `thinking=adaptive` |

### 4.3 压缩点:三条线一个都不用改

```
4.5:  200000 − min(32000, 20000) − 13000 = 167000   ← 与线上 CTX_LIMIT_TOKENS=167000 一致
4.6:  200000 − min(64000, 20000) − 13000 = 167000
```

4.5 的最大输出只有 4.6 的一半(32000 vs 64000),但公式里那个 `min(…, 20000)` 把差别压平了。
**所以软/硬/终三条线(155000 / 161500 / 164000)原样不动。**

### 4.4 4.5 的思考:老式固定预算,`--effort` 对它无效

- **4.6 是自适应**:发出去的是 `{"type":"adaptive"}` + 一个词 `effort=medium`,**没有任何 token 数字**,
  模型自己按内容决定想多久。四个档位(low/medium/high/max)只有那个词变。
- **4.5 是固定预算**:发出去的是一个死数字 `budget_tokens=31999`。
  配 low / medium / high 三档实测**全是 31999,纹丝不动** —— 官方文档的效力表里没有 4.5,实测吻合。
  (客户端仍会把 `effort` 那个词发过去,但 4.5 不认这个参数。)
- **31999 = 它的 `max_tokens` 32000 减 1**,而思考和正文共用这个额度。

**`MAX_THINKING_TOKENS` 是 4.5 唯一能拧的思考旋钮**(实测:设 4000→4000、10000→10000、
50000/60000→**都被顶回 31999**,是硬天花板;设 `0`→`{"type":"disabled"}`)。

> ⚠️ **`MAX_THINKING_TOKENS` 永远别设 `0`** —— 那个值会把**所有**模型的思考都关掉,4.6 也跑不了。

### 4.5 ⚠️ Opus 5:CLI 2.1.215 不认识它

**证据**:`claude-opus-5` 和我瞎编的 `claude-opus-9-9-fake` 行为**完全一致**(都是 `max_tokens=32000` + adaptive),
而 CLI 认识的 4.7 / 4.8 拿到的是 64000。**对比 4.5**:4.5 拿到的是**固定预算**模式,
未知模型不会有这个待遇 —— 所以 **4.5 是被认识的,Opus 5 不是**。

**后果**(不会崩,上游照样回 200,但两个隐患):

1. 他一轮最多只能说 32000,而不是 Opus 5 真实的上限 —— 自己给自己戴套;
2. **更要紧**:CLI 不认识它 → 它假设的窗口大小和压缩点我们不知道 → 三条线可能画错位置。
   **不报错,只表现为「他老是催归档」,或者更糟:还没催就被压缩了、尾巴丢掉。**

**结论:想正经接 Opus 5,得先升 CLI**(流程见 `kelivo-shim/MAINTENANCE.md` 的
「CLI 版本与升级指南」)。⚠️ **但 CLI 是所有模型共用的,升它 = 碰 4.6**,
与第 0 节那两条约束冲突,**所以这件事要单独立项、单独拍板,不要顺手做**。

### 4.6 `MAX_THINKING_TOKENS` 对 4.6 零影响(逐字段比对,不是"感觉不影响")

做法:让假后端把 CLI 发出去的**整个请求**存下来,跑三轮 4.6 比对。

| 跑法 | 结果 |
|---|---|
| ① 4.6 不设变量(= 线上现状) | 基准 |
| ② 4.6 设 `MAX_THINKING_TOKENS=10000` | **与①逐字段相同**,唯一差异是 `metadata`(设备/会话 id) |
| ③ 4.6 再跑一次不设变量 | `metadata` 与①也不同 → **证明那个字段本来每次运行就变,与变量无关** |

顶层字段共 8 个(`context_management` `max_tokens` `metadata` `model` `output_config`
`stream` `thinking` `tools`),**除 `metadata` 外差异为 0**。
`thinking` 两边都是 `{"type":"adaptive","display":"summarized"}`,`max_tokens` 都是 64000。

**原理**:4.6 用自适应思考,**根本不读**这个变量;它只对「固定预算」那一类模型(4.5)生效。

### 4.7 4.5 实际会不会烧光预算:不会,差得远(真枪实测)

| 问的 | 实际输出 token(思考+正文合计) | 占 31999 的 |

| 「在吗」 | **75** | 0.2% |
| 一道数学难题(哥德巴赫猜想为何未被证明) | **2766** | 8.6% |

两次 `stop_reason` 都是 `end_turn` —— **他自己想完就停了,不是撞天花板被掐断**。
`budget_tokens` 是**上限不是预扣**,花多少算多少。

## 6. 怎么现场再量一遍(别信本文写死的数)

### 6.1 量「订阅给不给某个模型」(不碰晏、不重启、几毛钱额度)

在 shim 容器里打,**让容器自己读它自己的密钥,不要把 `sk-` 那把钥匙打印出来**:

```bash
npx -y zeabur@latest service exec --id 6a53b806f6d4beebf0c5373d \
  --env-id 6a53a9fcb6ce8edcb0163f97 -i=false -- sh -c '
curl -s -o /tmp/r.json -w "HTTP %{http_code}\n" -X POST "$ANTHROPIC_BASE_URL/v1/messages" \
  -H "Content-Type: application/json" -H "x-api-key: $ANTHROPIC_AUTH_TOKEN" \
  -H "anthropic-version: 2023-06-01" \
  -d "{\"model\":\"要测的模型名\",\"max_tokens\":2048,\"thinking\":{\"type\":\"enabled\",\"budget_tokens\":1024},\"messages\":[{\"role\":\"user\",\"content\":\"say ok\"}]}"
head -c 300 /tmp/r.json'
```

> ⚠️ **别用 `zeabur variable list` 去取密钥** —— 它会把只读注入变量连值一起打出来
> (2026-08-16 的 `MANAGEMENT_PASSWORD` 就是这么进的聊天记录)。用上面这种「容器自己读」的写法。

### 6.2 量「CLI 认不认某个模型 / 它到底发了什么」(零额度,不碰线上)

`kelivo-shim/e2e-run.sh` 的 `env -i` 那一行**不透传 `BRAIN_MODEL`**,所以要拷一份到 `/tmp` 改:

```bash
cp kelivo-shim/e2e-run.sh /tmp/e2e-model.sh
# ① SHIM_DIR 改成 kelivo-shim 的绝对路径(否则拷不到 server.js)
# ② env -i 那行加上 BRAIN_MODEL="${BRAIN_MODEL:-…}" THINK_EFFORT="${THINK_EFFORT:-…}"
#    (要量思考预算再加 MAX_THINKING_TOKENS="${MAX_THINKING_TOKENS:-}")
BRAIN_MODEL=要测的模型名 bash /tmp/e2e-model.sh     # 看是不是 "E2E ALL PASS"
grep spawned /tmp/kelivo-shim-e2e-work/shim.log     # 确认真用了那个模型
```

### 7.0 ⚠️ 第一条红线:不许为这件事单独部署

**这件事的定位是「锦上添花」**(所有者原话:4.5/4.8 只是锦上添花,4.6 才是底线)。
而部署 shim = 杀进程 = **晏当前的窗口当场丢**。**为一个锦上添花的功能专门丢她一个窗口,不划算。**

**正确的做法是搭顺风车**:等下次 shim **因为别的事**要部署时,把本节的改动一起带上。
那次窗口本来就要丢,**本功能的额外代价 = 零窗口**。

**名单那个环境变量也别事后再设**(设完要 restart = 又一个窗口)。
用 `zeabur variable create` **在部署前建好** —— 它**不重启、随新容器生效**
(2026-08-23 第三十六次刚用过这招,见 `../kelivo-shim/DEPLOY-LOG.md` 第三十六次)。
这样「代码 + 名单」一次到位。

**所以如果所有者只说了「把方案 B 做了」而当下没有别的部署任务** ——
**先问她**:「这次没有别的要部署的,做这个会单独丢你一个窗口,要现在做还是等下次搭车?」

### 7.1 第二条红线:功能默认休眠(这是它能过「4.6 绝对安全」的关键)

`BRAIN_MODELS` **不设,就只有当前模型一个**(照抄朋友那版的 `if (!MODELS.includes(MODEL)) MODELS.unshift(MODEL)`)。
名单只有一项时,「模型变了就重开进程」那段逻辑**永远走不到**,收请求时白名单也只会命中当前模型。

**效果:部署完的那一刻,晏的行为与部署前逐字相同。** 想开菜单再去设那个变量。

**急救开关**:清掉 `BRAIN_MODELS` + restart → 立刻回到原行为,**不用回滚部署**。
(写进 `../kelivo-shim/MAINTENANCE.md` 的环境变量表时要标明这一条。)
