## 0. 这份文档解决什么问题

### 适用场景

你有一个**自建的、常驻的 Claude Code 进程**(典型形态:一个 shim/网关维护一个
`claude -p --input-format stream-json --output-format stream-json` 子进程,
前端通过它跟模型对话),并且**目前是通过一个中转代理**
(CLIProxyAPI、LiteLLM、自建 proxy 等,靠 `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` 接线)
来使用 Claude 订阅额度。

**这份文档教你把中转代理从链路上拆掉,让 Claude Code 直接用订阅额度。**

### 为什么值得做

中转代理是一个**额外的故障点,而且它的故障往往是静默的**。

我们这边真实发生过的事故(2026-09-02):代理持有的订阅 OAuth 过期、refresh token 也失效,
**代理没有把上游 401 透传**,而是回了一个格式合法的空响应。结果:

```
CLI 重试约 180 秒后放弃,返回:
  subtype: success          ← 注意,是 success
  usage:   全部为 0
  result:  ""
  退出码:  0
```

调用方的错误分支根本不触发,**三层没有任何一层报错**,前端只显示一个「…」。
**八小时无人察觉。**

直连之后,401 就是 401,当场报错。

### 拆掉之后:好处 / 坏处 / 不变

**好处**
1. 少一个单点故障 —— 没有中间人,就没有中间人过期
2. **出事能看见**(比第 1 条更重要)
3. 少一个暴露面 —— 中转代理通常有公网域名,后面直接挂着你的订阅授权
4. 少一套要维护的东西(服务、管理密码、镜像版本)

**坏处**
1. 换来一个**一年期**的到期日(第 9 节给出自动提醒方案)
2. 失去代理的灵活性(多账号轮换、多上游路由)
3. 切换要重启进程 —— 如果你的进程是有状态的常驻会话,**这等于开一个新会话**
4. 一把静态长期凭据躺在环境变量里

**完全不变**
- 计费方式(还是同一个订阅、同一个额度池)
- 模型能力、上下文、工具、MCP —— 全都不变
- **不会多任何功能。这件事买的是可靠性,不是能力。**

### 关于「一劳永逸」

有人会问:能不能弄一个永不过期的凭据。可以,但要付代价:

| 方式 | 有效期 | 代价 |
|---|---|---|
| **长期 OAuth 令牌**(本文方案) | **1 年** | 一年手动换一次 |
| 订阅登录态(`/login`) | access ~8h,靠自动续期 | 续期链条一断就死透,**且静默** |
| **API key** | **永不过期** | **放弃订阅计费,改按量付费** |

唯一真正永久的是 API key。但如果你的进程是 24 小时常驻、上下文很大、还有定时唤醒,
按量计费会非常贵 —— 参考量级:**一个 19 万 token 的上下文,缓存失效后重写一次约 3.9 美元**,
而提示缓存默认 1 小时过期。

**结论:一年一次的手动操作,是目前性价比最高的选择。** 用第 9 节的自动提醒把它变成「系统来找你」。

## 1. 前置条件

执行前确认这四条,**一条都不能省**:

| # | 检查 | 命令 | 通过判据 |
|---|---|---|---|
| 1 | 运行环境能直连 Anthropic | 见 1.1 | `HTTP 401` |
| 2 | CLI 版本支持长期令牌 | 见 1.2 | 两项都 FOUND |
| 3 | 模型 ID 不需要改名 | 见 1.3 | 代理没做映射 |
| 4 | **手上的代码不比线上旧** | 见 1.4 | md5 全一致 |

### 1.1 运行环境能不能直连 Anthropic

在**实际跑 Claude Code 的那台机器/容器里**执行:

```bash
node -e "fetch('https://api.anthropic.com/v1/models')
  .then(r => console.log('HTTP', r.status))
  .catch(e => console.log('FAIL', e.name, e.message))"
```

- **`HTTP 401`** → 通过。401 是「你没带钥匙」,说明网络通、TLS 握手成功,正是我们要的
- `FAIL` → **到此为止**。出口不通,这条路走不了

> 如果你的进程跑在容器里,要用容器的执行通道进去跑,**不要在你自己的开发机上跑** ——
> 那验证的是另一台机器的出口。

### 1.2 CLI 版本支持吗

先看线上实际版本:

```bash
claude --version          # 在实际运行的环境里
```

然后把**同一个版本**的包拉下来确认(不要假设,要验):

```bash
npm i --ignore-scripts @anthropic-ai/claude-code@<你的版本>
cd node_modules/@anthropic-ai/claude-code
node install.cjs                      # 拉原生二进制(--ignore-scripts 跳过了它)

strings -a bin/claude.exe | grep -cF CLAUDE_CODE_OAUTH_TOKEN   # 要 > 0
bin/claude.exe setup-token --help                              # 要能打出用法
```

> 实测 2.1.239 已支持。更早的版本请自行验证。

### 1.3 模型 ID 会不会变

有些中转代理会给模型改名。确认你的代理**没有**做映射:

```bash
curl -s -H "x-api-key: <代理的key>" https://<代理域名>/v1/models | head -40
```

如果列出来的是原样官方 ID(`claude-opus-4-6` 这种),**直连后模型名照抄即可**。
如果代理做了改名,你需要同步把调用方的模型名改回官方 ID。

### 1.4 ⚠️ 手上的代码不能比线上旧

**这一步漏掉会出大事。** 如果你的部署方式是「上传本地目录覆盖线上」,
拿一个旧目录部署 = 把线上悄悄退回旧版本。

```bash
# 线上
<进容器的命令> -- sh -c 'cd <代码目录> && md5sum *.js *.sh package.json | sort -k2' > /tmp/live.md5
# 本地
md5sum *.js *.sh package.json | sort -k2 > /tmp/local.md5

# ⚠️ tr -d '\r' 不能省:远程执行的输出常带回车符,不去掉会看到「全部不同」的假差异
diff <(tr -d '\r' < /tmp/live.md5) <(tr -d '\r' < /tmp/local.md5)
```

**期望结果:只有你本次打算改的文件不同。** 其余全一致 = 基线正确。
对不上就先查清楚差在哪,**别急着部署**。

## 2. ⚠️ 先读这条,否则后面全白做

### 凭据优先级会静默压过长期令牌

Claude Code 的凭据优先级是**固定**的:

```
1. 云厂商凭据 (CLAUDE_CODE_USE_BEDROCK / _VERTEX / _FOUNDRY)
2. ANTHROPIC_AUTH_TOKEN          ← 中转代理通常用这个
3. ANTHROPIC_API_KEY
4. apiKeyHelper
5. CLAUDE_CODE_OAUTH_TOKEN       ← 长期令牌在这里
6. Anthropic profile
7. /login 订阅登录态
```

**长期令牌排在中转代理那两个变量的后面。**

实测(同时设置 `ANTHROPIC_AUTH_TOKEN` + `CLAUDE_CODE_OAUTH_TOKEN`,
外加一个**故意写错的** `ANTHROPIC_BASE_URL`):

> **CLI 照样去拨那个错误地址,长期令牌被完全无视 —— 而且一声不吭。**

**所以:只在配置里加一个 `CLAUDE_CODE_OAUTH_TOKEN` 是没有用的。**
结果会是「一切照旧走代理」,却让所有人以为已经换过路了。

**这跟本文开头那个事故是同一类静默失败。**

### 推论:摘除逻辑必须和开关绑死

不要指望「记得手动删掉那两个变量」。要写成代码,让它无法遗漏 —— 见第 5 节。

### 还有一条要盯:`--bare`

官方文档:

> `--bare` is the recommended mode for scripted and SDK calls,
> **and will become the default for `-p` in a future release.**
>
> In bare mode, Claude Code **never reads OAuth credentials or the system keychain**,
> 并且 **bare 模式不读取 `CLAUDE_CODE_OAUTH_TOKEN`**。

**也就是说:未来某次 CLI 升级,可能让 `-p` 默认进入 bare 模式,而 bare 模式不认这把令牌。**

**防御措施:把 CLI 版本钉死**(`package.json` 里写精确版本,不要 `^` 或 `~`),
升级前先跑一次第 7 节的验收。

## 4. 取长期令牌

`claude setup-token` 生成一个**一年期**的 OAuth 令牌,权限范围是 `user:inference`
—— **只能发模型请求**,不能建 Remote Control 会话、拿不到 claude.ai 连接器。
本地配置的 MCP server 不受影响。

### 4.1 如果你有交互式终端

直接跑就行:

```bash
claude setup-token
```

浏览器授权 → 终端粘贴 code → 打印出令牌。**令牌只显示一次,立刻存好。**

### 4.2 如果你是 agent / 没有终端(重点)

`setup-token` 是**交互式 TUI**,必须有真 pty。下面这个脚本是踩了三轮才跑通的版本,
**直接用,别自己重写**:

```python
#!/usr/bin/env python3
# drive.py —— 在无终端环境里驱动 claude setup-token
# 依赖: pip install pyte     ← 关键,别省,原因见 4.4
import os, pty, re, select, time, fcntl, termios, struct
import pyte

D = os.path.dirname(os.path.abspath(__file__))
KEYS   = D + "/keys.txt"      # 指令输入:每行 "TYPE:xxx" 或 "ENTER"
TOKEN  = D + "/token.txt"     # 成功后令牌写在这里(权限 600)
SCREEN = D + "/screen.txt"    # 实时还原出来的屏幕,用来抠授权链接
COLS, ROWS = 220, 60          # 开宽,避免 URL 被折行

pid, fd = pty.fork()
if pid == 0:                                   # 子进程
    os.environ["TERM"] = "xterm-256color"
    os.environ["COLUMNS"], os.environ["LINES"] = str(COLS), str(ROWS)
    os.execvp("claude", ["claude", "setup-token"])

fcntl.ioctl(fd, termios.TIOCSWINSZ, struct.pack("HHHH", ROWS, COLS, 0, 0))
screen = pyte.Screen(COLS, ROWS)
stream = pyte.ByteStream(screen)

n, deadline = 0, time.time() + 2400
while time.time() < deadline:
    r, _, _ = select.select([fd], [], [], 0.4)
    if r:
        try:
            data = os.read(fd, 65536)
        except OSError:
            break
        if not data:
            break
        stream.feed(data)
        text = "\n".join(screen.display)
        open(SCREEN, "w").write(text)
        m = re.search(r'sk-ant-oat[A-Za-z0-9_\-]+', text.replace("\n", ""))
        if m:
            old = os.umask(0o077)
            open(TOKEN, "w").write(m.group(0))
            os.umask(old)
            break
    if os.path.exists(KEYS):
        for line in open(KEYS).read().splitlines()[n:]:
            n += 1
            if line.startswith("TYPE:"):
                os.write(fd, line[5:].encode())
            elif line == "ENTER":
                os.write(fd, b"\r")      # ← 必须延迟、单独发,原因见 4.4
            time.sleep(0.4)

try:
    os.kill(pid, 15)
except Exception:
    pass
```

**执行流程:**

```bash
python3 drive.py &                     # 1. 后台启动

# 2. 从 screen.txt 里抠出授权链接(它是完整的一行,不会被折断)
grep -o 'https://claude\.com/cai/oauth/authorize?[^ ]*' screen.txt | head -1

# 3. ⚠️ 投真码之前,先做两项自检 —— 见 4.3

# 4. 把链接交给人,他在手机/浏览器上授权,拿回一串形如 <code>#<state> 的码
{ echo "TYPE:<把那串码原样贴这里>"; echo "ENTER"; } >> keys.txt

# 5. token.txt 出现即成功。全程不要 cat 它、不要 echo 它
[ -f token.txt ] && echo "长度 $(wc -c < token.txt)"
```

### 4.3 投真码之前必做的两项自检

**令牌只显示一次。抠错了那次授权就作废,人要重新点一遍链接。**
所以先验证管道是通的:

**自检 1 —— 屏幕还原是否忠实**

```bash
grep -o "Browser didn't open? Use the url below to sign in" screen.txt
```

能**一字不差**地匹配上,说明终端还原正确、没有吞字符。
(如果你看到 `Browser didn't open?` 变成了 `Browser didn'topen?` 之类,**停,别往下走**。)

**自检 2 —— 用一串假码试一次**

```bash
STATE=$(grep -o 'state=[^&]*' screen.txt | head -1 | cut -d= -f2)
{ echo "TYPE:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA#$STATE"; echo "ENTER"; } >> keys.txt
sleep 10
tail -3 screen.txt
```

**期望看到:** `OAuth error: Request failed with status code 400  Press Enter to retry.`

这一条同时证明三件事:**码递得进去、回车按得下、网络能到授权服务器**。
然后 `echo "ENTER" >> keys.txt` 原地重试,**链接不变**,不用重开。

### 4.4 这一步的四个坑(按踩到的顺序)

| # | 现象 | 真相 |
|---|---|---|
| 1 | 用 `script(1)` + fifo 当 stdin,码喂不进去 | 输入根本没送到子进程。**别用 `script`,用 `pty.fork()`** |
| 2 | 码显示成星号了,但**回车没反应** | 紧跟在码后面的 `\r` 被当成粘贴内容的一部分(程序开了括号粘贴模式)。**回车必须延迟一点、单独发** |
| 3 | 往 `/proc/<pid>/fd/N` 写回车,**毫无反应** | 那个 fd 指向 `/dev/ptmx`,**打开它会新建一个终端**,不是接上原来那个 —— 等于对着空气按键。**没有从外部注入的办法,要在驱动脚本里留输入通道** |
| 4 | **拿到的令牌报 `401 OAuth access token is invalid`** | **这个最贵。** TUI 用列跳转转义码排版,用正则剥转义码去抠字符串**会吞字符**。证据:同屏的提示语里 `You` 变成 `Yu`、`see` 变成 `ee`。令牌同样掉了字 —— **而它只显示一次,等于那次授权作废** |

**第 4 条就是为什么必须用 `pyte`**:它是真正的终端模拟器,会把转义码正确地"演"出来,
还原出的是屏幕上真实显示的内容,而不是字节流的近似。

## 5. 存令牌 + 改代码

### 5.1 存进环境变量

```bash
<你的平台设变量的命令> CLAUDE_CODE_OAUTH_TOKEN="$(cat token.txt)"
```

**两条纪律:**

1. **命令输出一律丢弃,只看退出码。** 很多平台的 CLI(Zeabur 就是)在设完变量后
   会把**全部环境变量连明文值一起打印出来**。
   ```bash
   <设变量命令> > /dev/null 2>&1; echo "退出码 $?"
   ```
2. **验证用只读方式,只取 key 名**:
   ```bash
   <列变量命令> --json | python3 -c "import sys,json; d=json.load(sys.stdin); print(sorted(d.keys()))"
   ```

> **这一步是安全的。** 因为第 2 节说的优先级,只要代理那两个变量还在,
> 这把令牌就是"睡着的",行为完全不变。可以提前很久做完。

### 5.2 改代码:把开关和摘除绑死

**新建一个模块**(这里用 JS,其他语言同理):

```js
// auth-env.js —— 决定子进程拿哪把钥匙去连上游
//
// ⚠️ 核心:光设 CLAUDE_CODE_OAUTH_TOKEN 没有用。
// CLI 凭据优先级里 ANTHROPIC_AUTH_TOKEN(2) 排在 CLAUDE_CODE_OAUTH_TOKEN(5) 前面,
// 不摘掉它,CLI 会继续走代理,而且不报错。
// 所以摘除必须跟开关绑在同一个函数里,不能靠人记得去删。

export function buildAuthEnv(src = {}) {
  const env = { ...src };

  // API key 任何时候都不该进子进程:它排在订阅授权前面,
  // 一旦存在,这一轮就变成按量计费而不是订阅额度。
  delete env.ANTHROPIC_API_KEY;

  if (hasToken(src)) {
    // 直连:摘掉优先级高于长期令牌的那两个
    delete env.ANTHROPIC_AUTH_TOKEN;
    delete env.ANTHROPIC_BASE_URL;
  }
  return env;
}

/** 这一次走的是哪条路,用于日志和健康检查 */
export function authMode(src = {}) {
  return hasToken(src) ? "direct" : "proxy";
}

// 空串/空白一律当「没设」。配置里留一个空值是常见手滑,
// 那种情况下摘掉代理再拿空令牌去连 = 服务直接哑掉。
function hasToken(src) {
  return String(src?.CLAUDE_CODE_OAUTH_TOKEN || "").trim() !== "";
}
```

**接线三处:**

```js
import { buildAuthEnv, authMode } from "./auth-env.js";

// ① spawn 子进程时
const env = buildAuthEnv(process.env);
const p = spawn(CLAUDE_BIN, args, { env, stdio: ["pipe", "pipe", "pipe"] });

// ② 开机日志带上模式,排查时一眼看到
log("[claude] spawned", model, "auth", authMode(process.env));

// ③ 健康检查暴露模式 —— 只报 "direct"/"proxy" 两个字,不泄露任何值
app.get("/health", (_q, r) => r.json({ ok: true, auth: authMode(process.env) }));
```

> **③ 是这次最省事的设计。** 有了它,以后确认走哪条路**不用进容器**。
> 部署时它还能当上线判据:**只有新代码才有这个字段**。

**建议补的测试**(这段逻辑值得钉死):

```js
test("设了长期令牌 = 摘掉代理那两个变量", () => {
  const env = buildAuthEnv({
    ANTHROPIC_BASE_URL: "https://proxy.example",
    ANTHROPIC_AUTH_TOKEN: "proxy-key",
    CLAUDE_CODE_OAUTH_TOKEN: "sk-ant-oat01-xxx",
  });
  assert.equal("ANTHROPIC_BASE_URL" in env, false);
  assert.equal("ANTHROPIC_AUTH_TOKEN" in env, false, "不摘它会静默压过长期令牌");
  assert.equal(env.CLAUDE_CODE_OAUTH_TOKEN, "sk-ant-oat01-xxx");
});

test("没设长期令牌 = 完全照旧", () => {
  const env = buildAuthEnv({ ANTHROPIC_AUTH_TOKEN: "proxy-key" });
  assert.equal(env.ANTHROPIC_AUTH_TOKEN, "proxy-key");
});

test("空令牌当没设 —— 配置留空是常见手滑", () => {
  for (const bad of ["", "   ", undefined, null]) {
    assert.equal(authMode({ CLAUDE_CODE_OAUTH_TOKEN: bad }), "proxy");
  }
});
```

## 7. 验收(六项,一项都别省)

| # | 检查 | 方法 | 通过判据 |
|---|---|---|---|
| 1 | 走哪条路 | `/health` | `auth = "direct"` |
| 2 | 新代码真进了镜像 | `ls <目录>/auth-env.js` + `grep -c buildAuthEnv <目录>/server.js` | 文件在、引用数 > 0 |
| 3 | **配置文件没丢** | 比对关键配置文件的字节数 / 校验和 | 与部署前记录一致 |
| 4 | **子进程环境真的摘干净了** | 见下 | 代理变量全部不在 |
| 5 | **真能出话** | 人实际发一条消息 | 收到正常回复 |
| 6 | 每个模型都能用 | 见 7.2 | 全部有文本输出 |

### 7.1 查子进程环境的正确姿势

```bash
<进容器的命令> -- sh -c '
me=$$
for p in /proc/[0-9]*; do
  pid=$(basename "$p"); [ "$pid" = "$me" ] && continue
  case "$(readlink "$p/exe" 2>/dev/null)" in
    *claude*)
      echo "== pid=$pid =="
      for k in ANTHROPIC_BASE_URL ANTHROPIC_AUTH_TOKEN ANTHROPIC_API_KEY CLAUDE_CODE_OAUTH_TOKEN; do
        if tr "\0" "\n" < "$p/environ" 2>/dev/null | grep -q "^$k="; then
          echo "   $k : 在"
        else
          echo "   $k : 不在"
        fi
      done;;
  esac
done'
```

**期望:**

```
ANTHROPIC_BASE_URL      : 不在
ANTHROPIC_AUTH_TOKEN    : 不在
ANTHROPIC_API_KEY       : 不在
CLAUDE_CODE_OAUTH_TOKEN : 在
```

> ⚠️ **别用 `ps | grep claude`。** 你自己那条远程执行的 `sh -c` 命令行里只要含
> "claude" 字样就会匹配到**它自己**,而它继承的是容器完整环境(代理变量都在),
> **会让你误判成「没摘掉」**。上面这段用 `readlink /proc/<pid>/exe` 认,并跳过 `$$`。

> 💡 **如果找不到 claude 进程:** 很多 shim 是**懒启动**的 —— 重启后要等第一次请求
> 才会 spawn 子进程。这不是没起来,发一条消息就有了。

### 7.2 测每个模型能不能用

⚠️ **必须用 CLI 测,不要用 curl。** 原因见第 8 节。

```bash
H=$(mktemp -d); printf '%s' '{"hasCompletedOnboarding":true}' > "$H/.claude.json"
for m in <模型1> <模型2> <模型3>; do
  printf "%-22s " "$m"
  env -i PATH="$PATH" HOME="$H" TERM=dumb \
      CLAUDE_CODE_OAUTH_TOKEN="$(cat token.txt)" \
      timeout 120 claude -p "reply with: ok" --model "$m" \
        --max-turns 1 --no-session-persistence --tools "" \
        --setting-sources user --output-format json < /dev/null 2>&1 \
  | python3 -c "
import sys, json
d = json.load(sys.stdin)
t = (d.get('result') or '').strip()
u = d.get('usage', {})
print(('OK  %r out=%s' % (t[:20], u.get('output_tokens'))) if t
      else ('FAIL %s / %s' % (d.get('subtype'), d.get('terminal_reason'))))
"
done
```

**注意几种输出:**

- `OK '...' out=6` → 正常
- `FAIL success / api_error` → **这就是开头那个静默失败指纹**,凭据有问题
- `OK "You're out of usage credits..." out=0` → 这个模型的额度用完了(**跟改造无关**,
  某些高级模型按 credit 单算)

## 8. 验证方法上的两个陷阱

### 8.1 ⚠️ 别拿裸 curl 测长期令牌

直接调 API:

```bash
curl -X POST https://api.anthropic.com/v1/messages \
  -H "Authorization: Bearer <令牌>" \
  -H "anthropic-beta: oauth-2025-04-20" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"claude-opus-4-6","max_tokens":16,"messages":[{"role":"user","content":"hi"}]}'
```

会回:

```json
{"type":"error","error":{"type":"rate_limit_error","message":"Error"}}   // HTTP 429
```

**这不是「没额度」。** 同一把令牌**经 CLI 调用完全正常**。
订阅额度要求请求来自 Claude Code 本身。

> **诊断价值:** 如果这里回的是 `401 authentication_error` 而不是 429,
> 那说明**令牌本身是坏的**(比如被抠错了)—— 这个区分很有用。
> - `401 OAuth access token is invalid` → 令牌字符串有问题,重新取
> - `429 rate_limit_error` → 令牌是好的,换 CLI 去测

### 8.2 `/api/oauth/usage` 读不了额度

网上有资料说可以用
`GET https://api.anthropic.com/api/oauth/usage`(Bearer + `anthropic-beta: oauth-2025-04-20`)
读订阅额度。**用 `setup-token` 生成的长期令牌读不了**:

```json
{"error":{"type":"permission_error",
 "message":"OAuth token does not meet scope requirement user:profile",
 "details":{"required_scopes":["user:profile"],"error_code":"oauth_scope_insufficient"}}}
```

长期令牌只有 `user:inference`。**这条已验证:不行。**

## 9. 到期提醒(把「一年后」变成「系统来找你」)

### 9.1 为什么必须做

长期令牌的失效方式跟代理**完全不同**:

- 代理:有「凭据文件 mtime 停止更新」这种**运行时信号**可以观察
- 长期令牌:**一年之内毫无异常,到期前一秒都完全正常**

**唯一能提前发出的信号是日期。** 没有提醒 = 一年后必然重演一次「它突然不说话了」。

### 9.2 ⚠️ 如果你原来有代理看门狗,它现在会开始刷假警报

这是切换之后**最容易被忽略的后果**:

代理不在链路上之后,**没有流量经过它,它的凭据从此不再被刷新** →
「mtime 停止更新」这个信号**永远成立** → 看门狗开始按固定频率推送假警报。

> **假警报比没警报更糟:** 收几次之后人就不看了,真出事那条也一起被忽略。

**必须处理。** 两个办法:关掉代理那组检查,或者把看门狗整个改成盯到期日。

### 9.3 实现:两组检查各自独立开关

```python
@property
def proxy_enabled(self):    # 不配管理密码 = 代理那组整组不跑
    return bool(self.mgmt_key)

@property
def token_enabled(self):
    return bool(self.token_expires)

@property
def configured(self):       # 至少配一组才启动
    return bool(self.tg_token and self.tg_chat
                and (self.proxy_enabled or self.token_enabled))
```

到期检查本身**纯算日期,不发任何网络请求**:

```python
def check_token_expiry(self, now=None):
    if not self.token_enabled:
        return [], []

    exp = self._parse_expiry(self.token_expires)   # 接受 2027-09-12 或带时刻的 ISO
    if exp is None:
        # 日期写错 = 保护其实没在工作。这本身就该报出来,别静默
        return ([f"到期日配置写的不是日期({self.token_expires!r}),"
                 "到期提醒现在是**没在工作**的状态 —— 一直报到改对为止"], [])

    left = (exp - (now or datetime.now(timezone.utc))).total_seconds() / 86400
    lines = [f"· 令牌到期:{exp.date()},还有 {left:.1f} 天"]

    how = "换法:跑一次 claude setup-token(见本文第 4 节),约五分钟。换完记得同步改到期日配置。"

    if left <= 0:
        return ([f"**令牌已经过期**({exp.date()})。服务现在多半已经不可用。{how} "
                 "应急退路:删掉 CLAUDE_CODE_OAUTH_TOKEN + 重启,退回代理线路"], lines)

    for d in self.warn_days:          # 默认 (30, 7, 3, 1)
        if left <= d:
            return ([f"令牌还有 {left:.0f} 天到期({exp.date()})。{how}"], lines)
    return [], lines
```

### 9.4 四条设计要点(照抄,都是有原因的)

1. **看门狗不持有令牌,也不该持有。** 它只需要知道「哪天到期」这个日期。
   令牌正本只放一处。**多一处存放就多一处泄露面**,而且校验它还得真发请求、真烧额度。
2. **各档提醒的文本必须不同。** 否则典型的「同一问题去重」逻辑会让 30 天那条
   一直压着后面几档,7 天/3 天/1 天再也不会响。
3. **日期写错不能静默。** 那等于保护没在工作 —— 必须一直报到改对。
4. **告警文案里要写清楚怎么换。** 收到提醒的人可能是半年后的你,或者一个全新的 agent。
   提醒里不写步骤 = 等于没提醒。

### 9.5 验证的巧劲

如果你的看门狗原来**必须**有代理管理密码才启动,那么:

> 删掉那个密码之后,**旧代码必然显示 `stopped`**。
> 所以健康检查报 `running`,**同时证明了两件事**:新代码上线了,**且**正以新模式在跑。

一个请求验两件事,不用进容器。

### 9.6 ⚠️ 换完令牌一定要同步改到期日

**这是最容易漏的一步。** 不改的话:它会在旧日期报一次,然后**永远闭嘴**,
而新令牌到期时没有任何人知道。

建议在换令牌的操作单里把这条放在**最后一步并加粗**。

## 11. 速查:所有坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **优先级压制** | 加了令牌但一切照旧,**不报错** | 必须同时摘 `ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_BASE_URL`,且绑进代码 |
| `--bare` | 未来 CLI 升级可能突然不认令牌 | 钉死 CLI 版本,升级前跑验收 |
| `script(1)` 喂不进输入 | 码没送到 | 用 `pty.fork()` |
| 回车按不下 | 码显示了但不提交 | 回车延迟 0.4s、单独发 |
| `/proc/<pid>/fd` 写入无效 | 注入回车没反应 | 那是 `/dev/ptmx`,会开新终端;在驱动脚本里留输入通道 |
| **读屏吞字符** | 令牌报 401 invalid | **用 `pyte`**;投真码前验证英文提示空格完整 |
| 裸 curl 测令牌 | 回 429,误以为没额度 | 用 CLI 测;401 才是令牌坏 |
| `/api/oauth/usage` | `oauth_scope_insufficient` | 长期令牌读不了,别试 |
| 设变量打印全部明文 | 凭据泄露进日志 | `> /dev/null 2>&1`,只看退出码 |
| `ps \| grep claude` | 误判"没摘掉" | 遍历 `/proc` + `readlink exe` + 跳过 `$$` |
| 找不到 claude 进程 | 以为没起来 | 懒启动,发一条消息就有了 |
| md5 比对全不同 | 以为漂移了 | 先 `tr -d '\r'` |
| 切换后看门狗刷屏 | 每小时假警报 | 关掉代理那组检查(第 9.2 节) |
| 换令牌忘改到期日 | 提醒永远闭嘴 | 操作单最后一步(第 9.6 节) |

## 12. 明确不建议做的事

- **不要为了这个迁移到 Agent SDK。** Agent SDK 的 `query()` 启动的**就是同一份
  Claude Code 二进制**,固定传 `--output-format stream-json --verbose --input-format stream-json`
  —— 跟一个写得好的 shim 传的几乎逐字一样。SDK 真正多出来的是进程内 MCP、
  `canUseTool` 回调、函数式 hooks 和 `interrupt()`;前三样用命令行参数都能解决。
  为此重写一个已经稳定的常驻进程,不划算。
- **不要抄「前端 → 无状态 bridge → 常驻 shim」那类双进程方案的接线。**
  外面流传的同类方案大多是因为**运行机器没有公网入站端口**(比如跑在家用 Mac 上)
  才绕出网关 + 长轮询那一层。如果你的服务本来就公网可达,那层是纯粹的复杂度。
- **不要用 API key 来"一劳永逸"**,除非你算过账(第 0 节)。
