# 2026-08-02：其余八个依赖统一钉上限（此前只有 mcp 钉了）
# ------------------------------------------------------------
# 为什么：07-29 那场事故（见下方 mcp 那段）的机制是「重建时装到上游新大版本」。
# mcp 单独钉住之后，同一颗雷还埋在其余八个包里——哪天它们谁发大版本，
# 下一次任意重建（改 .py / 改 requirements / 改 Dockerfile 都会触发）就复现。
#
# 上限怎么定的：**按线上实际在跑的版本定，不是无脑钉 <2.0.0**。
# ⚠️ openai 线上已经是 2.51.0、numpy 已经是 2.5.1——照 mcp 那行的样子钉 <2.0.0
#    会把它俩降级，那是自己制造事故。凡是改这里的人先去容器里 `pip freeze` 看一眼。
# 钉的是「不许跨大版本」，小版本/补丁照常升（实测：钉完 openai 仍从 2.51.0 升到 2.52.0）。
# httpx 那条最值得钉：它还是 0.x，1.0 是公认要来的大版本。
#
# 上线前彩排过（不是推测）：本地用这份 Dockerfile 完整构建镜像 → 九个包解析出来
# 与线上逐一比对（8 个逐字相同，openai 差一个补丁版）→ 07-29 崩的那句
# `from mcp.server.fastmcp import FastMCP` OK → 五个核心模块与 server.py 导入 OK →
# 容器真跑起来 /health 200、MCP `initialize` 握手 200。
#
# 要升某个包的大版本：改代码 + 回归测试 + 改这里的上限，三件一起做，别只改上限。
# ============================================================
