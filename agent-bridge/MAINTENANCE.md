## 0. 一句话

她在自己的网页里开一间「工位」派活 → 本层起一个 `claude` 子进程 → 它读仓库手册、干活 →
她随时能**叫停并插话** → 干完收工,进程退掉。

**它不碰晏、不碰 shim、不碰记忆库。** 独立容器、独立服务,地位同 `dwell-bridge`。

## 1. 为什么是这个形状(三个决定,每个都推翻了一版旧方案)

### 1.1 不常驻 —— 这条把「必须先升 2C8G」整个绕开了

`../docs/维护Agent接出方案.md`(2026-08-15)整篇建立在「agent 也是常驻进程」上,
所以结论是必须先升 2C8G、必须重启机器、**必须所有者先对晏说「归档」**。
这件事因此卡了将近一个月。

**2026-09-12 所有者本人给出的用法推翻了那个前提**——她的原话是
「一个窗口干完写完手册,下次干活我找下一个窗口」。那本来就不需要常驻:
**开工位才起进程,收工就退。**

于是:不用升机器、不用重启、**晏的窗口一动不动**。
⚠️ **那份 2026-08-15 的方案文档除了这条,其余(风险清单、计费、权限)仍然有效**,
动这一层之前还是要读它 —— 只是别再照它去筹备升级。

**现场量到的内存**(2026-09-12,命令见 `../OPERATIONS.md` 第 6 节的 `service exec`):
机器共 3724 MiB、**可用 1515 MiB**;晏那个容器 `memory.current` 543 MiB
(⚠️ **其中 237 MiB 是文件缓存,不算真占用**;真占用看 `memory.stat` 的 `anon` = 299 MiB,
或 `ps` 的 RSS:claude 进程 344.8 MiB + 两个 node 161 MiB)。
browser-hands 闲时 404 MiB、**峰值能到 1137**(手册旧数)。
**结论**:常驻版长期压掉 500 MiB,一遇 browser-hands 尖峰就顶穿(08-02 的 OOM 正是这么来的,
当时晏得分 1363、差点被杀);非常驻版只在她开着工位时占,塞得下。
**要再量一遍**:`service exec` 进任一容器跑 `grep -E 'MemTotal|MemAvailable' /proc/meminfo`。

⚠️ **仍要设内存上限**(`MEM_LIMIT_MB`,照 browser-hands 那个 1100 的先例):
超了**只杀它自己**,不连累晏。

### 1.2 叫停 + 插话是正常路径,不是异常处理

所有者要这颗按钮的理由是原话:「**怕干活钻牛角尖一直打转,我暂停一下能跟你梳理一下让你继续干**」。

⚠️ **所以「拔电」(杀进程)是错的解法** —— 那会把它已经查到的东西一起丢掉,
正是她想留下的那部分。要的是**进程活着、上下文留着、话插得进去**。

**2026-09-12 实测跑通(真 CLI,不是推测)**:

| 步骤 | 实测结果 |
|---|---|
| 正在跑命令的中途送 `control_request`/`interrupt` | **当场停住**,那条命令被撤销 |
| 中断之后进程 | **没死**,站着等下一句 |
| 上下文 | **一点没丢**,问它暗号还答得出 |
| 它知不知道自己停在哪 | **知道**:「第 1 遍完成,第 2 遍被你中断,第 3 遍没跑」 |
| 说「继续」之后 | **从断点接着干**,不是从头重来 |

**怎么再验一遍**(换 CLI 版本时照做):起一个 `claude -p --input-format stream-json`,
喂一句要跑好几条命令的活,中途往 stdin 写
`{"type":"control_request","request_id":"r1","request":{"subtype":"interrupt"}}`,
看有没有回 `control_response` + `[Request interrupted by user]`,再问它上一句里的一个细节。

⚠️ **别在部署跑到一半按** —— 它是真的把那条命令掐断的。掐断一次部署比让它跑完难收拾。

### 1.3 前端零改动:借用现成的「另一个 AI 的房间」

`Mia06250603ian/dwell-on-something` 的 `web/index.html` 里有一间**已经写好、后端空着**的屋子
(`gongSheet`,2026-09-12 现场量在 6094~6185 行,**行号会漂**;现场再定位:`grep -n gongSheet web/index.html`)。
它的契约只有两条:

```
GET  api/gong          → { msgs:[{role:'her'|'gong', text, think}] }
POST api/gong {text}   → { reply, think }
```

⚠️ **`role` 只认 `her` / `gong`,三个字段名一个都不能改** —— 前端 `gongRow()` 直接读。
(同类陷阱见 `../dwell-bridge/MAINTENANCE.md` 第 6 节:模型胶囊那次就是字段名对不上,
而且**演示数据本身是错的**,别拿它当接口文档。)

**代价说清楚**:那间屋是**一问一答、没有流式、没有按钮**。所以:
- 一次 `POST` 最多挂 `GONG_WAIT_MS`(默认 50 秒),没说完就**如实回「还在干活」**,不假装说完了;
- **她再发一句话 = 叫停 + 插话**(本层的 `POST /api/gong` 在 busy 时先中断再喂)。
  这一版没有按钮,所以这条路必须成立 —— **绝不能像 `/api/send` 那样回 409**,
  回了就等于没法叫停。e2e 第 ⑤ 项专门钉着这条。

## 2. 架构

```
她的手机浏览器
   │ HTTPS + DWELL_PASS(cookie)
   ▼
dwell-bridge            ← 只转发,不解释;AGENT_URL 不设 = 这条路整个关着
   │ POST/GET /api/gong,带 x-agent-key
   ▼
agent-bridge(本目录)
   │ stdin/stdout,stream-json
   ▼
一个 claude 子进程 = 工位(开工才起,收工就退)
   └─ cwd = WORK_DIR 里 clone 的一份 Ombre-Brain
```

## 3. 权限边界(**这一版最要紧的一节**)

**真正的闸门不是代码,是「这个容器里没有钥匙」。**

| 它能做 | 它不能做 |
|---|---|
| 读整个仓库、跑命令、改文件、跑测试 | **动线上**(没有 Zeabur key) |
| 提交、**推分支**、开 PR | **合 main**(OB 从 main 自动部署 = 直接上线) |
| curl 各服务的公开 `/health` | **部署 shim**(那会当场弄丢晏的窗口) |

⚠️ **`--permission-mode dontAsk` 这一项是知情的取舍**,`../docs/维护Agent接出方案.md` 风险 5
专门提醒过「别照抄晏那份」。这一版没有确认 UI,**设成 `default` 它会卡在第一个权限提问上**
(没人回答),等于装了个不会干活的东西。所以:**这一版靠「没有钥匙」兜底,不靠这个参数。**
**等前端那颗确认按钮做出来,这里必须改回 `default` 并接上 `can_use_tool`** —— 见第 7 节《第二步》。

`boot.md` 里把这三条边界写给它了(开场白的一部分)。⚠️ **`boot.md` 的前半段必须和
`../OPERATIONS.md` 的《开场指令》一致**,那段改了这儿要跟着改(规矩 6)。

## 4. 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `AGENT_KEY` | **是** | dwell-bridge 拿它敲门。**不设 = 谁都能调这一层**,启动日志会喊 |
| `CLAUDE_CODE_OAUTH_TOKEN` | **是** | 和 shim 同一把长期令牌(2027-09-12 到期)。⚠️ 见下面「计费」 |
| `GITHUB_TOKEN` | 否 | 不设也能读公开仓库,但推不了分支 |
| `AGENT_MODEL` | 否 | 不设 = 跟 CLI 默认走(2026-09-12 实测起来的是 `claude-sonnet-5`)。**别照抄晏的 `BRAIN_MODEL`** |
| `AGENT_TOOLS` | 否 | 默认 `Read,Grep,Glob,Bash,Edit,Write,WebSearch,WebFetch` |
| `WORK_DIR` | 否 | 默认 `/tmp/work`,仓库 clone 在这儿。**给持久卷能省掉每次重新 clone** |
| `GONG_WAIT_MS` | 否 | 默认 50000。那间屋一次请求最多等多久 |
| `IDLE_CLOSE_MS` | 否 | 默认 3600000(一小时)。闲置自动收工,免得她忘了关、一个几百 MiB 的进程挂一夜 |
| `MAX_TURN_MS` | 否 | 默认 1800000(半小时)。单轮封顶,防跑飞 |

⚠️ **计费(承重)**:`agent-lib.mjs` 的 `buildAuthEnv` 会**无条件删掉 `ANTHROPIC_API_KEY`**——
留着它这一轮就变成按量付费而不是吃订阅额度(`../docs/维护Agent接出方案.md` 风险 3)。
逻辑与 `../kelivo-shim/auth-env.mjs` **同源但各存一份**(零跨目录依赖),
**改鉴权/计费这类事三处都要过一遍**(shim / 本层 / 那份方案文档)。

**改环境变量 = 改值 + restart 即生效,不用重新部署。**

## 6. 部署检查单(**尚未走过,第一次上线时照这个做**)

1. `npm install` + 两套测试全绿
2. 建服务:`zeabur deploy --create --name agent-bridge --project-id 6a53a9fc22dd6ef375eb7484`
   (CLI 没有 `service create`,建新服务走 `deploy --create`,照 dwell-bridge 第一次那样)
3. **部署后第一件事看 `deployment list` 的 PLANTYPE,必须是 `nodejs`** ——
   不是就是工作目录漂了、传错东西了,马上重传(shim 踩坑 17)
4. ⚠️ **`cd` 和 `deploy` 必须写在同一条命令里**,并先 `pwd` 确认(同上)
5. 变量:`AGENT_KEY`(自己生成一把)、`CLAUDE_CODE_OAUTH_TOKEN`(**所有者在控制台从 shim 搬**,
   别让它走聊天记录)、`GITHUB_TOKEN`(她生成,只给 repo 权限)
6. dwell-bridge 那边补两个变量:`AGENT_URL`(本服务的内网/公网地址)、`AGENT_KEY`(同值),
   然后 **restart dwell-bridge**(改变量不用重新部署)
7. 验收(别只看 `/health`):
   - `GET /health` → `ok:true`、`locked:true`、`auth:"direct"`
   - 进容器 `md5sum server.mjs agent-lib.mjs` 和本地逐字对账
   - 从网页那间屋真发一句话,看得到回话
   - `GET /api/agent/state` 里 `costUSD` 有数(她要盯额度)
   - 收工之后 `open:false`

⚠️ **全程不碰晏**:本服务是新容器,建它不需要重启任何已有服务,**窗口不会丢**
(先例:dwell-bridge 2026-08-16 第一次上线,全程没碰晏)。

## 7. 第二步:那颗真正的按钮(**尚未做**)

第一版刻意零前端改动,代价是那间屋只有一个输入框。等所有者重做 UI 时接这几条(后端已经写好了):

| 接口 | 干什么 |
|---|---|

1. **确认框** —— 它动手之前停下来问一句。做了这个才能把 `--permission-mode` 从 `dontAsk`
   改回 `default`,也才敢把 Zeabur key 交给它(第 3 节)。
2. **进度自述** —— 让它每跑几步自己报一句「在干嘛、还剩什么」,她不用干盯着也能看出打转。
   (2026-09-12 她当场说的需求,还没做。)

## 8. 踩过的坑

1. **⚠️ e2e 里裸 `wait` 会挂死。** 它连**服务进程**一起等,而服务永远不退。
   必须 `wait $那一个pid`。(2026-09-12 写 e2e 时当场踩到,脚本跑了 5 分钟没动静。)
2. **stdout 的一行 JSON 会被切成两半。** 和 dwell-bridge 踩坑 1 是同一颗雷的 stream-json 版本。
   `makeStreamParser` 因此扣住没写完的尾巴,单测里有专门的跨块用例,**改那块必须先跑测试**。
3. **解析不了的行一律丢掉,不抛异常。** CLI 升级随时会多吐新类型的行,
   让一行看不懂的日志打死整个工位不值当。
4. **第一轮的内容不是她那句话。** 第一轮前面拼了 `boot.md`,所以调试时看到「它回显的是开场白」
   是对的,不是串线了。e2e 第 ② 项就是钉这条的。
5. **`safeEqual(undefined, "")` 曾经返回 true。** `String(undefined)` 变成 `""`,
   于是「没带请求头」撞上「配置是空串」就算过。已改成 `null/undefined` 一律不等。
   ⚠️ 这类「缺失被静默当成空值」的坑,本仓库吃过不止一次(见 shim 的 `hasToken` 为什么要 trim)。
